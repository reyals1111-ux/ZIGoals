## Summary

Signing ZIGChain today means Keplr, full stop. ZIGChain mainnet (`zigchain-1`) is in Keplr's own chain registry (github.com/chainapsis/keplr-chain-registry, cosmos/zigchain.json, read 2026-10-18T18:43:55Z): bech32 prefix `zig`, coinType 118, `azig` with 18 decimals, Keplr-hosted `rpc-zigchain.keplr.app` / `lcd-zigchain.keplr.app`, gas steps low 2,500,000,000 / average 25,000,000,000 / high 50,000,000,000, plus stZIG (6 decimals). The testnet (`zig-test-2`) is not in Keplr's registry, so it stays a suggested chain; it is in cosmos/chain-registry under testnets/zigchaintestnet with the same fee numbers. The app's own `keplrChainInfo()` suggests average 2,500,000,000 and high 4,000,000,000, which is below both registries (and below the 25,000,000,000 azig/gas the owner's testnet transfer actually paid, per docs/research/ZIGCHAIN_CURRENT_STATE.md). Keplr Mobile signs via its in-app browser (deep link `https://deeplink.keplr.app/web-browser?url=…`) or WalletConnect v2 (`@keplr-wallet/wc-client` 0.13.41, still maintained, needs a Reown project ID); whether `experimentalSuggestChain` works over WalletConnect is undocumented and Keplr's source repository now returns 404, so it must be tested on a phone. Ledger signs ZIGChain only through Keplr (Cosmos app, coinType 118). MetaMask Cosmos snaps are not recommendable: Leap's snap died with Leap (shut down 28 May 2026; GitHub repo and snaps.metamask.io page both 404) and Mystic Labs' "Cosmos Extension" (`@cosmsnap/snap`) was last published 2024-05-29 with no audit status shown and no custom-chain support described. Leap (28 May 2026) and Cosmostation (1 September 2026) are confirmed ended; Mintscan went to Cosmos Labs, with no wallet successor. OKX, Trust and Citadel.one give no verifiable custom-Cosmos-chain support.

Read-only linking on desktop is already built the right way: EIP-6963 (Final) with `eip6963:requestProvider` / `eip6963:announceProvider`; rdns values from the RainbowKit source are `io.metamask`, `io.rabby`, `com.coinbase.wallet`, `com.trustwallet.app`, `com.okex.wallet`, `app.phantom`. Solana uses the Wallet Standard (`@wallet-standard/app` `getWallets()`, events `wallet-standard:app-ready` / `wallet-standard:register-wallet`, chain `solana:mainnet`, 1.1 kB gzip). Bitcoin stays typed single addresses; xpub needs `@scure/bip32` (a new dependency) because mempool.space has no xpub endpoint. On phones, without a Reown project ID, linking works only inside wallet in-app browsers (Keplr, MetaMask via `https://link.metamask.io/dapp/{url}`, Trust) or by typing an address.

Reown/WalletConnect, as of 2026-10-18: `@reown/appkit` 1.8.24 (271,901 B gzip per bundlephobia; Reown Community License with 500 MAU / 2.5 M RPC monthly thresholds before a commercial licence), `@walletconnect/sign-client` 2.26.0 (118,178 B gzip), `@walletconnect/ethereum-provider` 2.26.0 (139,148 B gzip). The lighter path is sign-client only plus deep links (Trust documents `https://link.trustwallet.com/wc?uri=`; MetaMask's `wc` links are undocumented with reported breakage). A project ID is public and ships in the bundle; domains are allowlisted in the dashboard (Configuration → Domain → "+ Domain" → Allowlist), and the CSP needs the relay, API, pulse and verify hosts listed in raw_notes.

Balances: ZIGChain and Cosmos Hub LCDs, every publicnode.com EVM/Solana endpoint, polygon-rpc.com, mainnet.optimism.io, mempool.space and blockstream.info all answer `access-control-allow-origin: *`; api.mainnet.solana.com and mainnet.base.org could not be confirmed on GET; arb1.arbitrum.io sends a duplicated `*,*`. Multicall3 is at 0xcA11bde05977b3631167028862bE2a173976CA11 on all six EVM chains. Prices need no Worker change: the coordinator already accepts any CoinGecko id in its catalog, and `cosmos`, `staked-zig`, `zignaly`, `ethereum`, `solana`, `bitcoin`, `usd-coin` are all present. Recommendation: browser-direct to official or publicnode endpoints on every chain (publicnode keeps nothing beyond 24 h; mempool.space keeps nginx logs 10 days), never an API-keyed indexer, and no pass-through route, since ZIGoals' own server would then see every address.

- **EIP-6963 (Final)**: dApp dispatches `new Event('eip6963:requestProvider')`; wallets dispatch `CustomEvent('eip6963:announceProvider', {detail: {info, provider}})`. `info`: `uuid` (UUIDv4), `name`, `icon` (data URI RFC-2397, square, ≥ 96×96, SVG via `<img>`), `rdns` (reverse-DNS, RFC-1034; "self-attested", not for feature detection). MetaMask/providers `src/EIP6963.ts` uses exactly these names and an FQDN regex on rdns.
- **rdns per wallet** (RainbowKit `walletConnectors/*` on main, 18:50:49Z): MetaMask `io.metamask`; Rabby `io.rabby`; Coinbase Wallet `com.coinbase.wallet` (also Reown AppKit `CONNECTOR_RDNS_MAP`); Trust `com.trustwallet.app`; OKX `com.okex.wallet`; Phantom `app.phantom`; Ledger: none (WalletConnect). Keep the app's "one per rdns" rule; add Trust, OKX and Phantom to `EVM_SUGGESTIONS` only with their official sites if install links are wanted (not checked here).
- **Phantom**: injects `window.phantom` on `https://`, `localhost`, `127.0.0.1`; not in iframes, not `http://`. EVM `window.phantom.ethereum` (`isPhantom`), Solana `window.phantom.solana` (`window.solana` legacy). Phantom docs do not mention EIP-6963 or the Wallet Standard; Sui deprecated. Supported chains per docs intro: Solana, Ethereum, Bitcoin, Base, Polygon, HyperEVM.
- **Wallet Standard (Solana)**: `import {getWallets} from '@wallet-standard/app'` (1.1.1, gzip 1,065 B); it adds `window.addEventListener('wallet-standard:register-wallet', ({detail: callback}) => …)` and dispatches `new AppReadyEvent` named `'wallet-standard:app-ready'`; `window.navigator.wallets` is the deprecated path. `wallet.chains` contains `'solana:mainnet'` (`SOLANA_MAINNET_CHAIN`), features keyed `'standard:connect'`, `'solana:signMessage'`, `'solana:signTransaction'`, `'solana:signAndSendTransaction'`, `'solana:signIn'`; accounts expose `address` (base58) and `publicKey` bytes. Read-only linking = `features['standard:connect'].connect()` then read `accounts[0].address` (no signing feature called). `@solana/wallet-standard` 1.1.8 (size unread).
- **EVM read-only** stays `eth_requestAccounts` (guard test). Note: `wallet_requestPermissions` is forbidden by the guard, so "address only" permissions are whatever the wallet grants for accounts.
- **Phones without a Reown project ID**: EIP-6963 and Wallet Standard work only where a provider is injected, i.e. inside wallet in-app browsers. Official deep links into in-app browsers: Keplr `https://deeplink.keplr.app/web-browser?url=<dapp>`; MetaMask `https://link.metamask.io/dapp/{url}` (MetaMask Connect page: EVM, Solana, multichain, "full wallet access without relay overhead"); Trust `https://link.trustwallet.com/<route>` or `trust://` (deeplinking page). Whether MetaMask Mobile's in-app browser announces EIP-6963 is not stated in its docs (reported in the wild; verify). Everything else on a phone needs WalletConnect (relay requires a projectId) or a typed address.
- **Ledger Live via WalletConnect**: Ledger Wallet supports WalletConnect v2 for Ethereum, Polygon, BSC and Solana accounts (support.ledger.com DE article, search result); it will hand back an address in the session namespaces → read-only EVM/Solana linking works once WalletConnect is in; no Cosmos.
- **Bitcoin**: keep typed single addresses (bech32/bech32m/base58 checks exist). xpub watch would need BIP32 derivation in the browser (`@scure/bip32` 2.4.0, MIT, unpacked 38,750 B; `@scure/base` 2.4.0; `@noble/hashes` 2.4.0) and N address queries (gap limit) against mempool.space (no xpub endpoint) — a new dependency, owner approval required.

## 6. Privacy — recommendation per chain and draft paragraph
Options: (A) the browser queries public endpoints directly (the address goes to that operator, as PRIVACY.md already says for ZIGChain); (B) a stateless same-origin pass-through (ZIGoals' own Worker sees every address; "never logs" cannot be proven because Cloudflare keeps infrastructure logs — PRIVACY.md already says so — and the C4 decision makes `/api/positions` refuse mainnet on public builds).
Recommendation: **A on every chain**, because the whole feature is "see the addresses you linked", the operator you choose can be named, and the app's promise "nothing of this leaves the device" for the public Alpha becomes "your browser asks the named public service directly, ZIGoals' servers are not involved". Per chain: ZIGChain → `api.zigchain.com` / `testnet-api.zigchain.com` (official, ACAO `*`, already disclosed); Cosmos Hub → `cosmos-rest.publicnode.com` (24 h retention stated) with `rest.cosmos.directory` as a fallback; Ethereum, Arbitrum, Base, OP, Polygon, BNB → the `*.publicnode.com` endpoints (ACAO `*`, no key, 24 h, no IP↔wallet correlation) rather than per-foundation RPCs with unknown CORS/logging; Solana → `solana-rpc.publicnode.com` (CORS verified) rather than `api.mainnet.solana.com` (CORS unverified, "not for production"); Bitcoin → `mempool.space` (ACAO `*`, 10-day nginx logs, no third-party trackers) with `blockstream.info` as fallback. Never an API-keyed indexer (Etherscan: the key would be public). Only one case argues for B: if the owner wants mainnet ZIGChain reads to keep going through `/api/positions` for consistency — but C4 refuses mainnet there on public builds, so A is the only path that works today without reopening that decision. Every chosen origin goes into `egress-policy.json` `chainOrigins`/`csp.app.connect`, and every read happens only when the person opens the wallet card for a linked address (never on page load), with `credentials:'omit'`, `referrerPolicy:'no-referrer'`.

Each of them sees your IP address and the public address you asked about; PublicNode says it keeps nothing longer than 24 hours and does not link addresses to IPs, mempool.space keeps its web-server logs for 10 days, and ZIGChain's policy is not published. ZIGoals' own servers are not involved and keep nothing. Nothing is sent until you open the card, no token list or holding is ever sent anywhere else, and prices come from ZIGoals' market service as before (public asset names only, never your address). Linking a wallet still makes no request of its own.
