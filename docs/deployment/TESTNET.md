# Testnet deployment runbook

Nothing has been uploaded or instantiated. `prepare-deployment.mjs` only reads testnet and computes a manifest; it has no signing/broadcast path. Never use raw target/*.wasm; use the validated artifact produced by the contract build script. No mainnet branch exists in these scripts.

1. Reproduce setup and all quality commands in README. Run `bash contracts/goal-manager/scripts/build-wasm.sh`; keep checksum, commit and version. Docker optimizer0.17.0 is the official-doc example but was not run (daemon unavailable); do not claim a container reproducibility check. Independent security review before broader users.
2. Owner obtains dedicated-wallet test ZIG through official support/faucet resolution, without repeated faucet requests. Never request/import a mnemonic. Public address is needed only for funding/whitelist verification when approval arrives.
3. After approval, inspect live upload permissions. Official documented CLI: `zigchaind query wasm params --chain-id zig-test-2 --node https://public-zigchain-testnet-rpc.numia.xyz`. This command was not executed here. Both tested REST params routes return501; treat failure or unavailable permission query as an unresolved gate, never permission to upload. Ask support for current query if needed.
4. Run `pnpm verify:network`, then `node scripts/prepare-deployment.mjs > /tmp/zigoals-prepared-manifest.json`. Review network/denom/version/checksum and `PREPARED_NOT_DEPLOYED` status. All absent live IDs/hashes remain null.
5. In a later authorized deployment session, owner reviews/simulates/signs code upload on testnet. Verify successful included transaction, code ID and onchain code checksum match the reviewed artifact. Upload is not instantiation.
6. Owner reviews/simulates/signs instantiate with native_denom from freshly verified config, optional pause admin explicitly agreed (default null), label `ZIGoals Goal Manager testnet`, and **no chain-level migration admin**. No attached coins. Check contract cw2 version0.1.0, code ID, denom, admin fields and empty solvency before enabling app.
7. Record a strict schemaVersion2 manifest using [MANIFEST_V2.md](MANIFEST_V2.md). Mark DEPLOYED only after upload/instantiate inclusion, exact code checksum/admin/cw2/denom reads and explorer verification. No fabricated placeholders. Validate structure with `node scripts/validate-deployment.mjs /path/to/public-manifest.json`; this does not prove onchain evidence.
8. Replace `apps/web/config/deployment.json` with that reviewed, validated public manifest and rebuild. Legacy address/code-ID environment variables no longer enable actions. Existing Keplr chain entry must show native azig with18 decimals; suggestChain may retain old metadata.
9. Owner signs a tiny create/deposit/partial/full-withdraw/close smoke test; test pause-with-exit if pause admin exists. Verify bank balances, recorded liabilities, event IDs, explorer paths, account switching and fees. Back up private metadata and test recovery against real onchain goals. Publish results separately from local tests.

Production app deployment and replacement of zigoals.app need explicit review. Current landing/index.html and landing/wrangler.jsonc remain unchanged. The latter is stored below landing while its assets directory says ./landing; existing external build/root settings were not inspected or changed. Do not relocate it based on assumptions.

M3 abort criteria: stop for missing/invalid/future schema, missing deployment receipts, unexpected chain version, stale/catching-up or wrong RPC, denomination mismatch, code/checksum/name/version mismatch, any chain migration admin, unexpected pause admin, dirty/unreviewed build, missing upload approval/funds or failed verification. Keep funds unsent. Optional pause admin defaults to null; the instantiate JSON is `{"admin":null,"native_denom":"azig"}`. A pause admin, if later explicitly approved, can pause creation/deposits but cannot block withdrawals or gain custody. Preparation and validation scripts accept no wallet/seed arguments and never sign. Any future CLI signer must be owner-operated official tooling with an approved OS-keychain/wallet mechanism; no hot-wallet helper is supplied.
