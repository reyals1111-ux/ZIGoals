# Testnet deployment runbook

Nothing has been uploaded or instantiated. Preparation only verifies a downloaded canonical artifact, reads public testnet evidence and returns `PREPARED_NOT_DEPLOYED`; it has no signing/broadcast path. Developer `artifacts/build-report.json`, local compatibility reports and single-build artifacts cannot enter this preparation path. Keep developer builds for local validation only. No mainnet branch exists in these scripts.

1. Review the source and all quality gates. Obtain the independently trusted full commit and its downloaded `REPRODUCIBLE` artifact directory from the successful canonical workflow. Follow [VERIFY_RELEASE_ARTIFACT.md](VERIFY_RELEASE_ARTIFACT.md) for actual bytes, size, schema, source/tree/lock/environment, trusted cosmwasm-check and workflow/run checks. An unsigned PR synthetic merge artifact may be prepared for inspection, but it is not an attested or upload-approved candidate. Before any future upload, require successful manual main-branch issuance and both Wasm/manifest attestations under the exact reviewed source and signer workflow. [Release issuance process](../release/RELEASE_PROCESS.md). Independent security review remains required before broader users.
2. Prepare read-only inspection data with explicit inputs. The source commit must exist in the separately reviewed local checkout. The optional trusted validator path defaults to this repository's `.toolchain/check/bin/cosmwasm-check`; neither environment variables nor downloaded metadata choose an executable. All local candidate verification completes before any network request or prepared JSON output. Network verification checks chain/denom/decimals/version and RPC readiness.

   ```bash
   node scripts/prepare-deployment.mjs "$EXPECTED_COMMIT" "$CANDIDATE_DIR" "$TRUSTED_VALIDATOR" > /tmp/zigoals-prepared-manifest.json
   ```

   Check exit status before using the output; shell redirection may leave an empty file after failure. Review source, checksum and `PREPARED_NOT_DEPLOYED`. All live IDs, addresses, receipts, admins and deployment/explorer timestamps remain null. Preserve the full canonical artifact manifest alongside this v2 deployment draft; the draft carries its source/hash and the schema's existing environment subset, not full provenance. Preparation is not an attestation or permission to upload.
3. Separately obtain explicit owner approval for the exact attested artifact checksum. The owner obtains dedicated-wallet test ZIG through official support/faucet resolution, without repeated requests. Never request/import a mnemonic. A public address is needed only for funding/whitelist verification when approval arrives. Missing funding or approval stops all transaction work.
4. After approval, inspect live upload permissions. Official documented CLI: `zigchaind query wasm params --chain-id zig-test-2 --node https://public-zigchain-testnet-rpc.numia.xyz`. This command was not executed here. Both previously tested REST params routes returned501; an unavailable permission query remains unresolved, never permission to upload. Ask support for a current query if needed. Recheck live network identity before signing.
5. In a later authorized deployment session, owner reviews/simulates/signs code upload on testnet using those exact downloaded bytes. Verify successful included transaction, code ID and onchain code checksum against the reviewed artifact. Upload is not instantiation. If submission/inclusion is uncertain, inspect the original transaction; do not rebuild, re-sign or rebroadcast as recovery.
6. Owner reviews/simulates/signs instantiate with native_denom from freshly verified config, optional pause admin explicitly agreed (default null), label `ZIGoals Goal Manager testnet`, and **no chain-level migration admin** (`--no-admin` for an owner-operated CLI). No attached coins. Check contract cw2 version0.1.0, code ID, denom, admin fields and empty solvency before enabling the app.
7. Record a strict schemaVersion2 manifest using [MANIFEST_V2.md](MANIFEST_V2.md). Mark DEPLOYED only after upload/instantiate inclusion, exact code checksum/admin/cw2/denom reads and explorer verification. No fabricated placeholders. Validate structure with `node scripts/validate-deployment.mjs /path/to/public-manifest.json`; this does not prove onchain evidence.
8. Replace `apps/web/config/deployment.json` with the reviewed, validated public deployed manifest and explicitly build with `NEXT_PUBLIC_APP_ENVIRONMENT=TESTNET_DEPLOYED`. Both deployed mode and the strict live-verified manifest are required; a manifest alone and legacy address/code-ID environment variables do not grant financial actions. The public undeployed Alpha stays `PUBLIC_ALPHA_UNDEPLOYED`. Existing Keplr chain entry must show native azig with18 decimals; suggestChain may retain old metadata.
9. Owner signs a tiny create/deposit/partial/full-withdraw/close smoke test; test pause-with-exit if a pause admin exists. Verify bank balances, recorded liabilities, event IDs, explorer paths, account switching and fees. Back up private metadata and test recovery against real onchain goals. Publish results separately from local tests.

The checked-in M4 draft was prepared read-only from the first successful unsigned [PR canonical run34767074194](https://github.com/reyals1111-ux/ZIGoals/actions/runs/34767074194), actual synthetic merge source `9a0f7681617e8fd98d1e44221bca7aab3bc4fcad`, Wasm255532 bytes, SHA256 `9ac9fec2941db7be4db13b4f6d7f8512b3d4fb87165e0284eaa10385782bea10`. The CLI reran source/byte/validator checks and public network reads. This draft is not final-source release issuance or attestation. All historical M1–M3 artifacts/reports retain their original evidence and are not current upload authority.

Production app deployment and replacement of zigoals.app need explicit review. Current landing/index.html and landing/wrangler.jsonc remain unchanged. The latter is stored below landing while its assets directory says ./landing; existing external build/root settings were not inspected or changed. Do not relocate it based on assumptions.

Abort criteria: stop for missing/invalid/future schema, developer/single-build artifact, changed bytes/source/toolchain, missing trusted main attestation before upload, missing deployment receipts, unexpected chain version, stale/catching-up or wrong RPC, denomination mismatch, code/checksum/name/version mismatch, any chain migration admin, unexpected pause admin, dirty/unreviewed source, missing owner upload approval/funds or failed verification. Keep funds unsent. Optional pause admin defaults to null; instantiate JSON is `{"admin":null,"native_denom":"azig"}`. An explicitly approved pause admin can pause deposits (goal creation remains available), but cannot block withdrawals or gain custody. Scripts accept no wallet/seed arguments and never sign. Any future signer must be owner-operated official tooling with an approved OS-keychain/wallet mechanism; no hot-wallet helper is supplied.
