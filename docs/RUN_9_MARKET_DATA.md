# Run #9 — market data, private accounting and history

CoinGecko is the only automatic provider. Set `COINGECKO_DEMO_API_KEY` in the gitignored `apps/web/.env.local`, restart the local server, and keep that file private. No `NEXT_PUBLIC_` key is supported. The server sends the credential only in `x-cg-demo-api-key`, with redirects disabled. Alpha secret provisioning and deployment remain separate owner-controlled steps; this run does neither. OpenNext normally embeds values from local environment files, so `build:alpha` removes the CoinGecko credential from its compiled environment module, scans the deployable artifact for that exact value, and removes the local production compilation cache. The Worker receives this key only through a separately provisioned runtime binding. The local `.env.local` remains intact; a sanitized Alpha preview has automatic pricing disabled unless a runtime binding is supplied.

## Coverage and provenance
Crypto and stablecoins use canonical CoinGecko coin IDs, with optional network/contract evidence; native mainnet ZIG maps explicitly to `zignaly`. Catalog symbol collisions stay separate selections. Stablecoins use actual market prices, never a $1 peg. Stocks, ETFs, Gold and Silver use **CoinGecko tokenized RWA reference** prices, not exchange execution prices or authoritative physical-metal spot. RWA quantities are reference units, never an automatic conversion from grams/troy ounces. Property and cash remain manual. Classification is the user's explicit choice.

`/coins/list?include_platform=true` and `/rwas/list` populate cached, locally searched catalogs. `/simple/price` batches coin IDs and quotes USD/EUR with actual provider `last_updated_at`. `/rwas/markets` batches RWA IDs in USD; it exposes no supported EUR quote parameter. RWA EUR valuation therefore requires explicit manual evidence; unlike currencies stay separate. See the [CoinGecko RWA markets API](https://docs.coingecko.com/reference/rwas-markets).

## Caching, boundaries and failures
Public quote evidence retains canonical identity, exact integer price plus decimals, currency, source, fetchedAt and observedAt only when supplied. A bounded exact-JSON parser preserves numeric lexemes and rejects duplicate keys. Quote freshness is 15 minutes, retry gates 60 seconds, catalog freshness 24 hours. User Refresh respects gating. Aging timers do not poll the provider. Surface mounts/identity changes fetch stale needed evidence. Malformed/failing responses retain last-good quotes and show the limitation.

The public cache key remains `zigoals:public-market-quotes:v1`; old native quotes hydrate. Capacity is 2,000 distinct pairs  / 2 MiB of public evidence. Client transport chunks 500 selected pairs, provider batches coin/RWA requests. Provider admission allows 12 requests per minute and at most 2 concurrently per process. These are process-local Beta controls, not a distributed quota service; many server instances can multiply usage. Watch the CoinGecko dashboard; `/key` is not used.

Only public provider identity and requested currencies enter the pricing API. No wallet, quantity, allocation, Goal ID/name, notes, contributions, Habit or Health data reach CoinGecko. Catalog/quote caches remain separate from private history. Manual total values take precedence. Ordinary Position edits preserve selected market identity/currency; entering a manual total deliberately switches to manual valuation.

## Private schema v3 and recovery
The existing `zigoals:platform:v1` key now stores schemaVersion 3. Valid v1/v2 reads migrate in memory without writes. The first explicit persisted mutation preserves exact v1/v2 recovery bytes. Automatic valuation history is gated until the active store is already v3. Confirmed new Local Demo operations can reconcile their evidence; viewing old v1 data does not force conversion. v1/v2/v3 backups import, invalid/future versions fail closed, and no damaged data silently resets. Health and Habits retain their independent schemas/stores.

Contributions are append-only exact-unit records with separate private/local Goal namespaces, optional Position/event-time valuation, evidence source, date and transaction reference. Reversals append equal opposite evidence and retain originals. The explicit Record history only mode changes history without changing Position quantities or allocations. Run #9.1 Fund Goal previews and commits new quantity, manual/quoted valuation, capped allocation and contribution evidence atomically. Surplus stays in owned wealth, available for other Goals. Existing observed wallet balances cannot be increased manually; use a separately tracked asset. Only validated persisted Local Demo receipts are reconciled, idempotently; preview actions create no record. Chain-confirmed facts require transaction references but no new chain execution is enabled. Goals with financial history must be closed instead of deleted.

Funding Wealth compares explicit net contributions with the **current** plan through today, derives future zero-return funding, required amount per remaining scheduled date, next date, shortfall/surplus and completion projection. Behind pace cannot be erased by appreciation. Historical plan edits appear in the timeline; previous contractual schedules are not reconstructed. An explicit scheduledDate on Fund Goal applies only its recorded compatible value toward that installment. Partial matches leave the remainder projected, and history reversal restores the credit. Other actual events remain unmatched. APR remains a separate scenario. Current unclaimed rewards, recorded claimed/distributed income and future scenarios are distinct. Annualized income rates are omitted.

## History and limits
Position quantity observations remain independent. Private valuation snapshots preserve entered quantity, price/source/currency/timestamps; Goal observations preserve the allocation/count evidence known then. Automatic capture is at most once per entity per UTC day, deduplicates unchanged evidence and never backfills market history. Retention caps are 240 Position valuation snapshots and 240 Goal history entries globally, with a 600,000-byte combined history budget, within the existing 2 MB private-store limit. Contributions/reversals are never compacted away; at the financial-record/storage ceiling further writes fail safely and backups remain available.

Charts show dated evidence points and accessible exact-value tables, with no invented interpolation. Wealth history requires complete comparable currency snapshots; missing constituents are not silently omitted. First-day/single-observation histories cannot establish a performance return. Closed Goals preserve history. Quote-driven wealth changes are never automatically attributed as contributions or income.

## Run #9.1 canonical assets and market history
Wealth is the canonical management surface. Stake / Positions filters manually tracked holdings to Crypto/Stablecoins alongside native observations. Archives retain Positions and financial evidence, release allocations only after explicit review, stop new capture, and affect subsequent totals by recorded lifecycle time. Position trackingStartedAt and up to 240 archivePeriods retain membership independently of the 240-item Activity feed. Edits preserve these facts; overlapping periods or a mismatched archive state fail import. All interval boundaries compare ISO timestamps as instants. Old v3 Positions without these fields retain their existing evidence fallback until an explicit asset edit migrates available lifecycle facts. Restore creates a lifecycle event without restoring old allocations. A bounded private watchlist holds up to eight exact public identities and never counts as ownership.

`POST /api/market-history` accepts only `{request:{marketRef,currency,range},refresh?}`. The server and client caches share pending work, retain last-good history, bound 24 windows / 2 MiB and 2,500 points per window, and enforce freshness/retry. CoinGecko `/coins/{id}/market_chart` supplies a 90-day window for detail charts; supported range buttons filter actual observations locally. RWA history is not requested; saved local unit-price observations remain private. Source: [CoinGecko Demo market chart reference](https://docs.coingecko.com/demo/reference/coins-id-market-chart).

The live Run #9.1 local adapter returned 2,161 Bitcoin/USD observations with HTTP 200; [recorded result](verification/run9-1/live-history-check.json). An earlier sandbox-constrained attempt had no network response. No paid endpoint, provider substitution or additional credential was used. The chart is contextual market evidence, never a reconstruction of portfolio ownership or investment return.
