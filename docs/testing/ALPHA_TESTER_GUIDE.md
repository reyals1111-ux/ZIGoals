# Alpha tester guide

Start with **Local demo**. It requires no wallet, account, funds, Docker or deployment. This unaudited alpha is not a savings account, investment service or recommendation. Simulated and testnet ZIG have no monetary value; mainnet and external strategies are disabled.

1. Open the official [public Alpha](https://alpha.zigoals.app/app), or follow [README setup](../../README.md#run-locally) and open `/app` and confirm `LOCAL SIMULATION`. Settings → Connection diagnostics shows the build version and selected environment.
2. Create a small fictional goal. Review its name, target, date and contribution. Starting amount is a planning input, not a deposit. Funding Health assumes zero investment return; projections and the demo's display conversion are illustrative.
3. Add simulated funds, withdraw part, withdraw the remainder, then close the empty goal. Compare the goal balance and simulated wallet balance after each action. No signature should be requested.
4. Export a Goal backup from Settings, change a fictional plan, then import the backup. It contains private plans only. Keep the file private. Try a backup from another scope and confirm refusal.
5. Open a second tab on the same origin. Changes should refresh there; a stale action review should require review again. Modes are selected per tab. Lock protection applies to participating tabs in this browser profile, not other devices.
6. Reload the app. It intentionally returns to Local Demo. After a previous successful connection in this tab, the app may offer **Reconnect Keplr**; click explicitly to reconnect. Keplr may reuse its remembered permission or ask to unlock/approve. No wallet method is called automatically. Clearing site data is destructive to local plans, the simulated ledger, Habits, Health records and recorded transaction history; test removal only with disposable fictional data. Do not clear data to resolve an uncertain testnet transaction.
7. Open **Habits** and create a fictional habit, such as a daily reading or walking reminder. Record a fictional check-in, edit the habit and confirm its history remains. If you link it to a fictional Goal, completing the Habit must not move funds or request a signature.
8. Open **Health** using synthetic test information only. Add a fake food or recipe, a fictional meal entry, a test weight reading or manually entered activity, and optional fictional targets. Check that the displayed summaries reflect only what you entered. Do not use real health information during Alpha testing.
9. In **Settings**, export separate Habits and Health backups. These readable JSON files can contain personal or health information, so keep them private. With fictional test data, change one module and restore its matching backup. Confirm the selected module is restored without replacing Goals or the other private module. Invalid, wrong-version or oversized backups should be refused rather than silently accepted.

**Optional connection-only Keplr check:** use the official extension and an existing dedicated development account. Verify the trusted origin and `zig-test-2`. Approve or reject connection and check the account and actual testnet balance. Zero real testnet ZIG must not become the simulated 1,000 ZIG. The owner's real hosted rejection/connection results are [recorded separately](../verification/m5/OWNER_LIVE_ALPHA_EVIDENCE.json). Creating another wallet solely for account-switch testing is not required.

**Stop at NOT DEPLOYED.** Funds and upload eligibility are still blocked. No tester should upload, instantiate, sign a Goal Manager action or retry the faucet for this run. A future separately reviewed deployment and explicit owner action are required. External provider/Hub/explorer links are informational and lead to separate services; they do not verify a transaction or enable a strategy here.

For bugs, record expected/actual behavior, minimal steps, build commit, OS/browser, mode, whether one or two tabs were used, and the public diagnostics timestamp. Use fictional or synthetic plan, Habit and Health data and crop/redact screenshots. Never share a mnemonic, private key, wallet password, token, full private backup, personal financial data or real health data. Use the [public bug form](../../.github/ISSUE_TEMPLATE/bug_report.yml) for ordinary defects and **hello@zigoals.app** for suspected security/privacy issues.

The official Alpha is **https://alpha.zigoals.app/app**; the fallback is **https://zigoals-alpha.reyals1111.workers.dev/app**. The official marketing domain is **zigoals.app**. Confirm the exact origin; do not trust similar-looking domains. [Current status](../STATUS.md) distinguishes the deployed source from changes awaiting owner deployment. Read the [Alpha disclaimer](ALPHA_DISCLAIMER.md) and [privacy notes](../PRIVACY.md) before entering information; use fictional plans and synthetic Health information for testing.

Check the persistent environment banner and build identity after a deployment or rollback. Public undeployed mode must never request a financial signature, including when a wallet is connected. If it does, reject the request, stop testing that build and report it privately. A browser-injected wallet mock is not proof that the real Keplr extension works under the hosted policy.

Plans, Habits, Health data and history belong to the browser origin. Switching from a preview URL to a custom domain starts a separate storage scope. Export/import the corresponding private backup yourself if needed; neither the host nor maintainers need the file. The web host sees request paths, including goal IDs, while private plan, Habit and Health content remains browser-local in the supported flows. No frontend rollback recovers deleted browser data.
