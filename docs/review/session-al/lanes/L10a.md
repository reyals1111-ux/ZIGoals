## Request to the integrator: the theme generator (root cause of NB-055 and others)
`scripts/themes/build-themes.mjs` maps a source rule already written for one theme a second time (e.g.
`:root[data-theme=light] .length-counter { background: #fff }` becomes `#242424` in light.css). Patch, in `buildTheme`'s
`ast.walkRules` loop right after the island check (tested on a scratch copy: light-keyed rules come through as written,
the dark sheet no longer carries them):

```js
const own = /\[data-theme=["']?(light|dark)["']?\]/.exec(rule.selector ?? '');
if (own && own[1] !== theme) return;
if (own) { const decls = (rule.nodes ?? []).filter(n => n.type === 'decl' && roleOf(n.prop, rule) && carriesColour(n.prop, n.value)).map(n => postcss.decl({prop: n.prop, value: n.value, important: n.important})); if (decls.length) rules.push({file, rule, decls, mapped: false}); return; }
```
Then regenerate `public/themes` from a clean tree.
