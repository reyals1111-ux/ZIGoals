# Run #9 — Goal Intelligence + Live Wealth

Local owner-review implementation on `codex/run9-goal-intelligence-live-wealth`, based on prep commit `a6950f7f7cfeeef0c5be286179e5bc99235d9a66`. No merge, push, deployment, wallet signing, contract operation or financial execution.

## Product and implementation

1. **Implementation:** server-only CoinGecko discovery/quotes, private schema v2, explicit financial records and deterministic Goal intelligence share canonical selectors across the product.
2. **Visible improvements:** a new Wealth hero, allocation overview and class cards; first-class Funding Health, actual-history entry and reversal; evidence charts and Goal timeline; financial next steps on Today and provenance in Activity.
3. **Modules:** `lib/server/coingecko.ts`, `market-assets.ts`, `exact-market-json.ts`, market cache/client/routes; `positions.ts`, `private-storage.ts`, `goal-intelligence.ts`, `local-contributions.ts`, `wealth.ts`, `goal-summary.ts`; asset search/manual source/Position editor, Wealth, Goal detail, Today and Activity components. No contract, Habit or Health data-model changes. See the branch diff for the complete file inventory.
4. **Schema/migration:** schemaVersion 2 uses the existing `zigoals:platform:v1` key. Valid v1 reads migrate in memory; passive visits do not overwrite v1. First explicit persistence retains original recovery bytes. Existing backup imports, damaged/future-store rejection, locking and multi-tab behavior remain covered.
5. **CoinGecko:** cached local catalog search; canonical asset selection; exact decimal coin/RWA parsing; header authentication; bounded batched requests; 15-minute freshness, 60-second retry gates, 24-hour catalogs; last-good retention and manual fallback.
6. **Coverage:** crypto, stablecoins and native mainnet ZIG in USD/EUR; tokenized RWA stocks/ETFs and Gold/Silver references in USD. Live sample: 21,335 coins + 817 RWAs, and 14 successful quote pairs including BTC/ETH/USDT/USDC/ZIG, Apple/NVIDIA/Gold/Silver. Stablecoins use observed prices. Catalog membership does not guarantee every asset has a current quote. Physical metal weights, property and cash remain manual.
7. **Contributions:** dated exact-unit contribution, withdrawal, income and reversal records; original entries retained; optional Position association and event-time valuation in the data model; private/local Goal namespaces; idempotent confirmed Local Demo receipt reconciliation. Preview actions, quantity edits, allocations, Habits and market appreciation never create financial records. Manual entry is expressed in the Goal's unit; it does not change balances or allocations.
8. **Timeline:** contributions, reversals, explicit Goal/plan/allocation changes, quantity observations and recorded valuations retain distinct provenance. Goal detail displays the latest 12 events; retained data remains in backups. Goals with financial records must be closed instead of deleted.
9. **Planned versus actual:** current-plan scheduled amount through today, exact net actual records, variance, next scheduled date and unmatched-record explanation. Historical plan versions are visible as changes but are not reconstructed as immutable obligations.
10. **Funding Health:** deterministic current wealth, remaining amount, current-plan pace, future planned amount, required contribution per remaining date, zero-return completion date, shortfall/surplus and warnings. Appreciation cannot erase missed contribution pace; stale/missing evidence cannot establish completion. APR remains a separate scenario.
11. **Rewards/income:** currently unclaimed allocated rewards, explicit cumulative claimed/distributed income and hypothetical future APR are separate. Income charts use dated records and reversals. No unsupported annualized run-rate is invented.
12. **History/charts:** actual evidence only, no backfill or inferred return. At most one automatic capture per entity per UTC day; unchanged evidence deduplicates. Up to 240 Position and 240 Goal history entries globally, combined 600,000-byte budget inside the existing 2 MB private-store ceiling. Financial records are not pruned. Charts show evidence points plus accessible exact-value tables; Wealth totals require complete comparable snapshots.
13. **Wealth:** tracked/allocated/available amounts, separate currencies, composition by class, selected valuation method, source/freshness state, explicit manual precedence, retry controls and local history.
14. **Today/Activity:** compact pace/action guidance and Goal links; actual private Goal records and confirmed Local Demo ledger activity; financial events remain distinct from Habit/Health activity and routine quote changes.
15. **Visual/UX:** nebula surfaces, gradient typography, orbit artwork, clearer metric hierarchy and responsive modules. Goal Detail, Wealth, Today and Activity checked at 1440, 390 and 320 CSS pixels; desktop/mobile captures are in `verification/run9/`.

## Limits and handoff

21. **Known limits:** process-local cache/quota admission (not distributed); bounded observations may shorten large-portfolio history; current-plan comparisons do not match specific historical instalments; recorded income has no annualization policy; history starts locally and does not attribute causal market return. Full details: [Beta backlog](RUN_9_BETA_BACKLOG.md).
22. **Provider-dependent deferrals:** RWA EUR is manual because the current CoinGecko RWA markets endpoint offers USD reference evidence, not a supported EUR quote parameter. Unsupported/unavailable assets stay manual; physical-weight conversion is never inferred. No second provider or paid endpoint was added.
23. **Privacy/security:** provider access uses the server-only key and request header, never query authentication. Market requests contain only public asset identity/currency; private quantities, wallets, Goals, notes, allocations, contributions, Habits and Health do not enter this boundary. No key value is included in docs, snapshots or source. Financial authority remains unchanged. Scans are evidence, not a claim of a comprehensive penetration test.
24. **Final HEAD:** exact final local branch HEAD is supplied in the owner handoff after committing this report. The starting prep commit remains an ancestor.
25. **Git status:** final worktree status is checked after the local commit and supplied in the owner handoff; no secret environment file is staged.
26. **Release boundary:** nothing deployed, merged or pushed. Alpha credential provisioning and rollout require a separate owner decision.
