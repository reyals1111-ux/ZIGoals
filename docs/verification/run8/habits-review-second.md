# Habits six-fix review

- **P1 — A dated Habit cannot be edited, paused, archived, or restored after its end date** (`apps/web/lib/habits.ts:56-57, 119-134`). Every state or content change creates a rule dated today while carrying the existing end condition; once `today > endCondition.date`, `ruleSchema` rejects that new rule. The same refinement also rejects any previously accepted V2 history containing a post-end state rule, making the whole private store fail closed on load. Validate a newly chosen end date against the Habit/change date without declaring historical post-end state rules malformed.
- **P2 — Changing an existing Habit to every-N-days does not start the new cadence prospectively** (`apps/web/components/habits/habit-editor.tsx:61-65`; `apps/web/lib/habits.ts:119-123, 137-142`). The editor anchors an interval edit to `habit.startDate`, while the new rule begins today. If that original date is off the new modulo, the Habit becomes “Not scheduled” immediately after save and first occurs later, despite the UI promising recurrence changes apply today onward. Anchor a newly selected interval to the rule-change date; retain the stored anchor only when editing an already-interval rule.
- Confirmed fixed from the original review: completion-count endings now use completed day/period outcomes; pause/resume and mid-period rule changes no longer create truncated failures; impossible frequency counts are rejected; cadence streaks are separated by unit; Goal target endings are disabled and labelled metadata-only; frequency targets display their actual schedule period.
- Natural-period review: incomplete first/last/mixed-rule/paused periods stay neutral; a resumed same-signature frequency period remains one outcome; completion limits stop only after the target day/period succeeds; historical entries and pre-change rules are not rewritten.
