# Finance integration fix review

- **P1 — Staking projections still admit a Position that the Goal explicitly rejects** (`apps/web/lib/positions.ts:135-145` versus `:124-125`). `allocatedNativePrincipal` checks network, verification and native denom, but omits the REWARD-Goal rule that only `NATIVE_REWARDS` may count. A schema-valid imported REWARD Goal allocation to `NATIVE_STAKING` therefore produces zero current Goal progress but positive “allocated principal” and projected rewards. Direct reproduction returned `{ progress: "0", principal: "1000000000000000000" }`. Apply the same Goal-type/source eligibility used by `goalProgress`.
- **P1 — Reconciliation can rewrite an unrelated Habit through a stale cross-store ID** (`apps/web/components/platform/tracked-detail.tsx:26, 29, 39-46`). The platform and Habit modules restore independently, and `contributionHabit` trusts `plan.habitId` without first requiring that the referenced Habit already links to this Goal. If a restored/stale ID resolves to another Habit, “Apply plan to contribution habit” rewrites its title, category, description, Goal link, schedule, type, measurement, target, end condition, and today’s rule. Refuse reconciliation on link mismatch and offer an explicit relink/create choice; do not mutate the referenced Habit merely because the UUID exists.
- **P2 — Creating the linked Habit is a non-atomic two-store operation with no recovery** (`apps/web/components/platform/tracked-detail.tsx:57`). The Habit is persisted before `plan.habitId`; if the platform write fails, the linked Habit remains but the plan still has no ID, so the UI continues offering “Create linked contribution habit” and retries create duplicates. Detect/reuse the uniquely linked template Habit or compensate the first write when the second fails.
- Confirmed fixed: both Goal views use `scenarioHorizon`; leap-day clamping and explicit deadlines are correct; `planScenario` supports long normal horizons and rejects its explicit 12,000-date ceiling; the reviewed reconciliation path preserves prior-day entry data and historical rules.
- Verification: `pnpm exec vitest run apps/web/lib/positions.test.ts` passed 20/20; `git diff --check` passed for the reviewed files. `platform-habits.spec.ts` covers successful reconciliation but not stale-link or partial-write failure paths.
