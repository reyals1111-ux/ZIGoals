# M4 independent Goal Manager engineering security review
Reviewed clean main `7d354e3c72fa671abc100facf908b247fb992cc0`; scope: M4 brief sections 26/46, all contract implementation/state/messages/errors, relevant tests, current threat model and deployment/build controls. Static independent review; not a professional audit.
Finding M4-C01 — LOW, documentation: `docs/deployment/TESTNET.md:17` says the pause admin can pause creation/deposits. `contracts/goal-manager/src/contract.rs:68–91` allows CreateGoal while paused; only Deposit checks pause at lines 95–98. Reproduction reasoning: PauseDeposits by configured admin, then CreateGoal by any sender with no funds succeeds and allocates an empty goal. This cannot take custody or bypass the deposit pause. Correct the runbook to “pause deposits”; retain the intended exit/creation behavior. No Critical/High/Important contract defect identified in this pass.
Ownership/admin: `contract.rs:170–180` checks stored owner and active status before all goal mutations; withdrawal recipient is stored owner at 126–130. `contract.rs:183–190` limits optional config admin to toggling deposits. No owner transfer, sweep, arbitrary call, reply, sudo or migrate entry point appears in `src/contract.rs`, `src/msg.rs`, or `src/lib.rs`; chain migration admin remains a separate deployment trust boundary.
Accounting/solvency: `contract.rs:99–110` credits exactly incoming configured native funds; 116–132 debits the same amount from goal and global liabilities and emits one bank send. Starting at zero, each successful financial transition preserves liabilities = sum(position_units) and bank = liabilities + unsolicited native surplus under the chain bank/atomic transaction assumptions. `contract.rs:241–254` reads the real native bank balance and flags deficits, with surplus clamped at zero; it does not sum unrelated assets.
Atomic exit/pause/close: `contract.rs:113–144` leaves withdrawals/empty closure available while paused, rejects zero/overdraw and nonempty closure, and retains closed history; `contract.rs:177–178` prevents closed reuse. Downstream bank-send rollback is explicitly exercised in `tests/integration.rs:545–580`; this reviewer inspected that test without rerunning the root baseline suite. Bank messages have no user-controlled recipient or external-contract callback.
Denoms/funds: `contract.rs:32–40` validates ASCII denomination length/grammar; short-circuit checks make empty denom indexing safe. `contract.rs:18–22,71,114,137,150,184` reject all attachments on nonpayable routes; 99–103 reject absent/zero/wrong/multiple deposit coins, including duplicate-denom entries. `tests/boundaries.rs:14–59,212–276` cover direct malformed coin vectors unavailable from normal bank normalization. Denom validity alone does not verify the intended chain asset; deployment preflight must do that.
Arithmetic/availability: `contract.rs:74,106–108,119–121` uses checked ID and Uint128 arithmetic before writes. `tests/boundaries.rs:62–208` inspects exhausted IDs, each deposit overflow, withdrawal-counter overflow and liability underflow. Lifetime deposit overflow eventually refuses further deposits into that goal but does not prevent withdrawing its existing balance; users can create another goal. No unbounded global iteration occurs in execution or solvency.
Queries/pagination: `contract.rs:213–239` returns stored config/goal/cw2 and idle position without deriving fake yield; owner index is inserted at 89, never reassigned, and read using validated owner prefix, exclusive ascending ID cursor, default 30/cap 100 (221–228). Zero limit returns empty. Closed entries remain queryable with zero position. `tests/integration.rs:947–989` exercises caps, tail, foreign cursor, max cursor and invalid owner.
Metadata/events: `contract.rs:159–167` accepts only 64 ASCII hex characters or null, normalizes case, and owner-only updates cannot touch balances; `contract.rs:201–208,111,124–125` emits action/goal/owner/denom/strategy and financial amount without commitment. Commitment remains public in state and input, is mutable until close and proves neither encryption nor correctness of the private preimage; `contracts/goal-manager/README.md:9` explicitly describes public visibility.
Malicious sequence review: traced cross-owner funding/withdraw/update/close, admin-as-attacker, repeated withdrawal, deposit+withdraw+close+reuse, pause+exit, unsolicited donations+withdraw, invalid funds and overflow. Inspected independent expected-ledger conservation assertions in `tests/invariants.rs:256–410` and seeded branch/drain coverage at 438–546; finite deterministic cases and static tracing are not exhaustive fuzzing or formal verification.
Identity/migration: `contract.rs:15–16,54–56,214` sets fixed cw2 name and package version on initialization and reads stored identity. `docs/deployment/OWNER_TESTNET_CHECKLIST.md:11–14` correctly requires null chain migration admin, separately verifies optional pause admin, and checks deployed code/checksum/identity. Absence of the current migrate export alone must never substitute for verifying null chain admin: a chain administrator could select replacement code with its own migration logic.
