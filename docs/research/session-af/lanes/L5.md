## 1. Part 10.1 — Sidebar sky parallax

**Mechanism (CSS first, rAF-free).** The three background layers stay on `.app-sidebar` exactly as AE drew them (stars `local`, ground `local`, colour), so the no-script, reduced-motion and Motion Off renderings are byte-identical to AE. The drift moves only the first layer's `background-position-y`:

```css
/* app/visual-v21.css, after line 58 */
@keyframes sidebar-sky-drift { from { background-position: center bottom, center bottom, 0 0; } to { background-position: center calc(100% + var(--sky-range, 0px)), center bottom, 0 0; } }
@supports (animation-timeline: scroll()) { @media (min-width: 901px) and (prefers-reduced-motion: no-preference) {
  :root:not([data-app-motion=off]) .app-sidebar[data-sky=timeline] { animation: sidebar-sky-drift linear both; animation-timeline: scroll(self block); }
} }
@media (min-width: 901px) and (prefers-reduced-motion: no-preference) {
  :root:not([data-app-motion=off]) .app-sidebar[data-sky=listener] { background-position: center calc(100% + var(--sky-scroll, 0px) * .55), center bottom, 0 0; }
}
```
At scroll 0 the sky is where AE pinned it; as the content scrolls up by `s`, the stars (which scroll with the content) are moved back down by `.55·s`, so they travel at 45 % of the content's speed and are never behind the same button twice. Light (`light.sidebar.css`, three layers in the same order: dawn stars, dawn gradient, colour) uses the same keyframes; Dark (`dark.sidebar.css`, four layers: veil, stars, ground, colour) gets `sidebar-sky-drift-dark` with the stars as the second layer. Why not `translate` on a pseudo-element (the owner's suggestion): a transformed layer inside the scroller extends the scrollable overflow by its own translation (a feedback loop unless the layer is shortened by the range), and pinning a pseudo to the content's end needs the measured `scrollHeight`; `background-position` needs neither and repaints a 216 px column only — recorded as an ADR row.

**Script (`components/shell/sidebar-sky.tsx`, mounted once in `shell.tsx` after `<aside>`, ≈ 0.6 kB gz, shell chunk).** Renders nothing. On mount and on a `ResizeObserver` of the sidebar and its direct children: `range = Math.round(.55 * (el.scrollHeight − el.clientHeight))` → `--sky-range: <range>px`; `data-sky="timeline"` when `CSS.supports('animation-timeline: scroll()')`, else `data-sky="listener"` with a passive `scroll` listener writing `--sky-scroll: <scrollTop>px` (one style write per event, coalesced by the engine; no rAF). Does nothing while `matchMedia('(prefers-reduced-motion: reduce)')` matches or `html[data-app-motion=off]` is set (a `MutationObserver` on `data-app-motion`). At ≤ 900 px (sidebar = header, `position:relative`) nothing applies.

**Tests.** `tests/sidebar-sky-af.spec.ts` (desktop, viewport 1280 × 560 so the sidebar scrolls): seed the Showcase; `aside.scrollTop = 240`; read `getComputedStyle(aside).backgroundPositionY` → the first layer's offset lies strictly between 0 and 240 px (moved, slower than the content); the planet's and the theme bar's `getBoundingClientRect().top` moved by exactly −240 (they scroll with the content); `page.emulateMedia({reducedMotion:'reduce'})` → `100%` (still); `zigoals:motion:v1 = 'off'` → still; the same in Light and Dark. Unit `components/shell/sidebar-sky.test.ts` (jsdom): the range maths and the timeline/listener choice.

## 2. Part 10.2 — Light redo: CSS architecture

**Principle.** Light = Nebula + (the page ground white with the AE mist) + (text ink) + (heavy animated backgrounds calm). The generator stays (it is the only way to reach the hundreds of literal colours in component CSS), but its policy changes from "remap every role" to "flip text and neutral surfaces, leave everything else alone".

**Token layer (Nebula, `app/visual-v21.css :root`, additive).** A computed "ink" twin for every small-text accent: `--pillar-goals-ink: var(--pillar-goals)`, `--pillar-habits-ink`, `--pillar-health-ink`, `--pillar-wealth-ink`, `--brand-cyan-ink`, `--brand-blue-ink`, `--brand-violet-ink`, `--brand-magenta-ink`, `--nebula-pink-ink`, `--nebula-warm-ink`, `--cyan-ink`, `--violet-ink`, `--pink-ink`, `--ring-emerald-ink`, `--ring-mint-ink` — in Nebula and Dark equal to their base (so the parity test sees no difference). Light redefines them on `:root[data-theme=light]` with the value the generator computes (same hue and chroma in OKLCH, lightness lowered until ≥ 4.5:1 on `#ffffff`). Components that set small coloured text from a token use the `-ink` twin (`color: var(--pillar-habits-ink)`); fills never do. For runtime per-element colours (`--pillar`, `--area`, `--tone`, `--event-accent` set inline) Light keeps one rule each, rewritten from `color-mix(... 38%, #0b1230)` (a hue shift toward navy) to relative colour syntax that keeps the hue: `color: oklch(from var(--pillar) min(l, .5) c h)` (`.life-ring-pillar`, `.hall-area`, `.health-hl-label`, `.activity-category-label`, `.template-area`).

## 4. Part 10.5 — The footer finale's ribbon

## 9. Part 9 — The three features (plus two alternates for the owner's pick)

### 9.1 My Universe
- **Model** `lib/universe/model.ts`: `universeOf({habits, health, platform, goals, extras, today, baseCurrency}) → {planets: Planet[], milestones: Milestone[]}`, `Planet = {pillar, light: 0–1 | null, rings, moons, facts: string[]}`. Goals: light = mean progress of goals whose value is known (unknown left out, never 0), rings = goals finished (`achievementsOf`), moons = milestones done. Habits: light = 28-day consistency (complete ÷ due via `habitDay`), rings = Σ⌊`habitStats().bestStreak` ÷ 30⌋ (cap 6), moons = habits with `currentStreak ≥ 7`. Health: light = share of the last 14 days with any log (water, food, sleep, weight; through the Health gate only), rings = ⌊nights logged in 90 d ÷ 15⌋, moons = fasts finished (`fastingHistory`). Wealth ("money working"): light = share of tracked wealth allocated to goals in the base currency (`wealthOverview`; null when nothing is tracked), rings = ⌊contributions ÷ 10⌋, moons = accounts tracked — never a price or a return. `milestones` are derived ids (`universe:habits:ring:1`, `universe:goals:moon:3`, `universe:first-light`) with a title and one plain line.
- **Store** `lib/universe/store.ts`: `zigoals:universe:v1 = {version:1, seen: {[id]: 'YYYY-MM-DD'}}` (loose, ≤ 500 ids, personal, device-only); `celebrate(state, id, today)`; a milestone shows once per device (its own map, independent of the game layer's `zigoals:celebrations:v1`, so the Universe works with Gamify off).
- **Scene** `components/universe/universe-scene.tsx`: inline SVG (no canvas, no dependency): a central light, four orbits, four planets in `--pillar-*` radial gradients, rings as ellipses, moons as small circles on each planet's orbit, brightness from `light`; `data-entrance=once` draws the orbits and fades the planets in (650 ms, `use-entrance`), nothing moves afterwards; reduced motion / Motion Off: the rest state; hover = the card's liquid-glass lift only (no pointer tracking). Labels ≥ 14 px, each planet a 44 px target opening its facts.
- **Mounts**: Today device card `universe` (compact: four planets in a row, one line of the newest milestone, "Open my universe →"), the full view on `/app/journey#universe` above the game sections (renders with Gamify off; the page title stays Journey; Journey stays in the nav only with Gamify on — the Today card is the door), "Share my universe" → `drawShareCard({eyebrow: 'My universe · {date}', title: '{n} rings, {m} moons', lines: facts, accent: pillar})` → `shareOrSave`. A milestone celebration (one calm card in `CelebrationHost`'s look) appears once on Today.
- **States**: empty → "Your universe is waiting for its first light. Check in a habit, log a day or set a goal."; loading → a 180 px skeleton; unreadable records → the Today cards' "needs attention" line; Showcase → the Showcase's records, nothing written.
- **Phones**: the compact card folds (`PhoneFold`); the full scene scales by `viewBox`; the facts as a 2 × 2 grid.

### 9.2 Day Timeline
- **Model** `lib/timeline/build.ts`: `buildDayTimeline({today, now, habits, health, reminders, plan, dayTimeline, fasting, meditation, extra}) → {blocks, nowMinute, quiet}`; `Block = {id, kind: 'habit'|'meal'|'sleep'|'fast'|'timer'|'meditation'|'reminder'|'checklist', title, start, end|null, pillar, href, done, movable, note?}` (minutes of the day). Sources: habits due today (`habitDay(...).scheduled`) at the device override → the habit's reminder time (`zigoals:reminders:v1`) → the `timeOfDay` default (morning 08:00, afternoon 14:00, evening 19:00; `anytime` → the "Anytime" shelf above the clock), length from the override → the duration target → 20 min; meals planned today (`weekPlan`'s slots for today) at the slot override → Breakfast 08:00, Lunch 12:30, Snacks 16:00, Dinner 19:00, 30 min; the sleep window from last night (`bedClock`/`wakeClock`) else the bedtime plan item (22:00) + 8 h, drawn in two parts across midnight; the running fast (start → target, `fastingTimeline`); running habit timers and the meditation run (now → remaining); reminders (water, the plan's items on their day); `registerTimelineSource(fn)` — the seam for the Checklist lane; until it lands the dots are Today's due habits (the closest honest "links to the Checklist": no Checklist exists on main).
- **Store** `lib/timeline/store.ts`: `zigoals:day-timeline:v1 = {version:1, times: {[key]: {time:'HH:MM', minutes?: 5–600}}}` with keys `habit:<id>` and `meal:<slot>` (loose, ≤ 300, personal, device-only — like the reminders key). Moving a reminder block edits the reminders record; moving the sleep window edits the bedtime plan item; fasts and running timers are not movable (lock icon, "A running fast keeps its own clock").
- **View** `components/timeline/day-timeline.tsx` (full) and `timeline-card.tsx` (compact: the now line and the next three blocks). Full: a vertical ruler 05:00–24:00 (earlier hours folded), 1 min = 1.2 px (desktop) / 1 px (phone), blocks absolutely placed, overlapping blocks in two columns, a "now" line (`setInterval` 60 s, cleared when hidden). Tap/click a block = complete (habit `smartDone`, meal "Log it" door, reminder dismiss) with Undo; **move** = pointer drag on the block's handle (`setPointerCapture`, 15-min snap, live time label) **and** keyboard (focus, ↑/↓ = 15 min, Enter, Esc) **and** a time picker in the block's ⋯ menu (the dragging alternative, WCAG 2.5.7). Plain words one tap away: "Times on this timeline are kept on this device."
- **Mounts**: route `/app/timeline` (new, own chunk, budget line; `metadata.title 'Timeline'`, the layout title template guard), the phone More sheet row "Timeline", search `page:timeline`, Today device card `timeline`, Habits' hero gets a "Today on the timeline →" link.
- **States**: no blocks → "A quiet day: nothing is scheduled yet. Give a habit a time or plan a meal."; loading skeleton; unreadable record → read-only view with the catalog line; Showcase → shown, moves refused with the Showcase toast.

## Risks

- Light contrast regressions: with chromatic fills and glows identity, some Nebula accents on white (e.g. cyan rings, light pastel chips) may read faint; the rule is the owner's; the audit's contrast run per theme and critique round 1 decide where a deeper *text* shade is needed (never a fill). The gradient headings' nebula part is knowingly below 3:1 by design.
- Gold text without the amber shift may read olive in Light (G22's finding); surfaced in round 1 captures for the owner's choice (keep the hue, or restore amber for text only).
- The parity test may flag legitimate Light hand rules (the hero pool, the dusk footer) as box or colour diffs; the allowed-class list must be tightened per finding rather than widened — every widening is an ADR row.
- Scroll-driven animations: Safari 26 / WebKit builds vary; the listener fallback covers it, but the parallax rate in the fallback path is only as smooth as scroll events (no rAF by design).
- Footer ribbon pieces: a seam or a gap between the three transform-revealed pieces at some width; mitigated by the shared sample and the six-width spec, but hairlines need a capture check in each theme.
- Today's first-load weight: default-on compact cards must stay in lazy sub-chunks; if the measured /app delta exceeds the 51 kB headroom, the Universe compact card renders a lighter static variant (no SVG gradients) rather than raising the budget.
- today-cards is a synced record: adding `off` and three ids is loose-safe, but a device on #37–#43 that saves the record keeps the unknown bytes only if its own write path is loose (it is: todayCardsSchema is looseObject since AA-Cloud); the frozen reader proves it before the Tier 3 commit.
- Drag on the timeline: pointer capture inside PhoneFold/scroll containers can fight the page scroll on iOS; the handle uses touch-action: none and a long-press-free immediate drag; the picker is the guaranteed path.
- Timeline semantics: device-only times may surprise a person expecting sync; the plain-words line and Known limitations say so; promoting the key to the life extras section is an owner decision for a later session.
- Stories' year window and the 3-day minimum are new product rules; an owner may want a different threshold — recorded as an ADR row, trivially tunable.
- The Journey page is game-gated and nav-registered only with Gamify on; the Universe full view there is reachable through the Today card and search — the owner may prefer a dedicated route (a one-line change plus a budget line).
- Parity suite run time: ~19 routes × up to 3 states × 3 themes × 2 projects; kept under the CI shard budget by one test per route and by skipping dialogs on the mobile project; if it still stretches a shard, the suite is split into two spec files.
- The capture tool is new in-repo dev tooling; the AE capture.mjs lives on an orphan branch not present locally — no dependency on it.

## Decisions proposed (see ADR-028 for the recorded ones)

- Sidebar parallax moves the stars layer's background-position with a scroll-driven animation (listener fallback), not a transform on a pseudo-element: a transformed in-scroller layer extends the scrollable overflow and pinning it to the content's end needs the measured scrollHeight; the rate is 45 % of the content's speed; reduced motion and Motion Off render AE's pinned sky unchanged.
- Light's generator policy: text and neutral surfaces/borders flip; every chromatic fill, border, glow, shadow and graphic is identity; gradient text is a role of its own and identity; small chromatic text is deepened to 4.5:1 in OKLCH keeping hue and chroma; the G22 amber hue shift is retired (same-hue rule) with the olive risk shown to the owner in round 1.
- Ink tokens (`--<token>-ink`) exist in every theme and equal the base in Nebula and Dark; Light computes them; components use them for small coloured text only, never for fills.
- Gradient headings keep the Nebula stops verbatim in Light (the owner's words); the ink part carries legibility; the decorative part is knowingly below 3:1 and is excluded from the contrast audit by class, recorded here.
- Islands stay (hero, footer, sidebar foot, launchers, art cards) except `.staking-card`, which follows the theme (owner 10.9).
- Light's two layout-shifting hero rules (margin-top 30/76 px) are removed so a theme switch never moves a box; the pool's fade is a mask on the pool itself.
