Change: new `apps/web/lib/vault/reconcile-once.ts`:
```ts
import {RevisionConflict} from './cloud-sync';
/** ADR-028 (ADR-027 G24): after the cloud answered 409 to a replayed or staged write (the journal has cleared the pending write), one more attempt re-reads the cloud and merges; a second 409 is reported as before. */
export async function reconcileOnce<T>(attempt: () => Promise<T>, fence: () => void, onRetry?: () => void): Promise<T> {
  try { return await attempt(); } catch (error) { if (!(error instanceof RevisionConflict)) throw error; fence(); onRetry?.(); return await attempt(); }
}
```

## Risks

- The `pages` synced schema (lib/pages/schema.ts, z.partialRecord over PAGE_IDS) is strict: a lane adding a hideable new route could make older builds refuse zigoals:settings:v1 — new routes are not hideable in AF unless a frozen-reader run proves otherwise.
- A2 depends on the body being readable after a navigation; an unreadable 503 stays an error (fail closed), which could keep a live run red if Chrome drops the body — the set-aside then needs a retry read before the asserts (recorded in the test).
- A3's ±2 s window is a heuristic; a real failure with errorText net::ERR_ABORTED (the page aborting its own fetch while idle) is still counted, but one inside a navigation window would be set aside — mitigated by the errorText rule and by recording every set-aside URL.
- A4 changes sync behaviour (one silent retry); the retry re-reads the cloud before any write, but the conflict review's expectations in other specs (sync-self-conflict, lost-ack) must stay green — run them in the integration set before pushing.
- The deterministic race test plants a pending write; if the Worker's CAS checks row revisions before the base, a copied row with revision+1 is needed (read workers/private-sync before writing the test).
- Option (a) adds a server-only egress origin and a 2 s resolver hop to recipe import; DoH outages fail the import closed (RESOLVER 502) — acceptable for a convenience route, stated in Help.
- Node on this Mac defaults to 22.23.1; every Terminal and every helper must export the fnm 24.19.0 path or pnpm doctor fails and builds differ.
- No flock/timeout on macOS: the shlock loop and the perl alarm wrapper must be used by every helper; a helper running a build outside the lock corrupts the suite's timing (memory: a second Playwright run wipes results).
- Full browser suite length (~2–3 h) and the audits' 6 widths × 3 themes: Gate C must start Sat 08:00 sharp; the freeze on Fri 22:00 is load-bearing.
- Run ids for Alpha #44 and the CI run on 4f92495 are not in the repo; they must come from the Actions API or stay as marked slots, never from memory.
- Shared registries: a lane editing app-nav, help-page, static.ts, everything.ts or egress-policy.json directly produces merge conflicts and double entries — the lane files are the only channel.
- The What's new release id and Help ids are pinned by three specs; the words must land in one commit with those specs updated at equal strength.
