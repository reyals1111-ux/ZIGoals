## 0. The shape in one paragraph
One **signing pipeline** (`lib/staking/`) with one gate (`issueSignTicket`, callable only from the review sheet's submit handler) feeds four features: Staking actions (Part 2), Goal Vault "re-stake rewards" (Part 6), governance votes (Part 6) and nothing else. **Keplr is the only signer** (R4: no other wallet signs ZIGChain today; Ledger signs through Keplr's amino path). Every other wallet is **read-only** through what AE built (`lib/wallet-link.ts`, EIP-6963) plus a Solana Wallet-Standard reader; balances are read **browser-direct** on non-ZIGChain chains (R4's privacy decision, no pass-through) and through the **existing relay** on ZIGChain (`/api/positions`, because `api.zigchain.com` answers 403 to the OPTIONS preflight that a coherent `x-cosmos-block-height` read needs — R5 LB11). Linked addresses and everything derived from them stay **device-only** (`zigoals:linked-wallets:v1` kept, additive fields), never synced, never restored. On-ramps (Part 4) are **redirects only** with public identifiers from one config file, empty by default. The practice/real split is one word everywhere: `PRACTICE · ZIGChain Testnet (zig-test-2) · no real value` vs `REAL · ZIGChain mainnet (zigchain-1) · real money`.

## 3. Signing pipeline and the single gate (`lib/staking/`)
```
messages.ts   pure builders returning EncodeObject[]: delegate({delegator,validator,amount}) '/cosmos.staking.v1beta1.MsgDelegate'; undelegate; redelegate({src,dst}) MsgBeginRedelegate; claim(validators[]) → one MsgWithdrawDelegatorReward per validator; vote({proposalId,option}) '/cosmos.gov.v1beta1.MsgVote' (amino converter exists in CosmJS 0.38.1 for Ledger; v1 has none). amount is always {denom:'azig', amount:<integer string>}; validator must pass isValoper (bech32 'zigvaloper', 20 bytes).
quote.ts      quoteStaking(network, address, action, msgs): lazy import('@cosmjs/stargate') → SigningStargateClient.connectWithSigner(rpcUrl, signer) → client.getChainId()===chainId → gas=client.simulate(address,msgs,'') → fee=calculateFee(ceil(gas*1.3), GasPrice.fromString('2500000000azig')) → liquid balance GET {rest}/cosmos/bank/v1beta1/balances/{addr}/by_denom?denom=azig (plain GET, no custom header, no preflight) → requires balance ≥ fee (+amount for delegate) → StakingQuote {network, address, action, msgs, gas, fee, feeAmount, balance, safeMax=safeMaximum(balance,feeAmount), unbondingSeconds (read live), isLedger, revision, expiresAt=now+60s}. The signer is needed by simulate (pubkey/sequence) but nothing is signed here; a unit test with a recording signer proves simulate never calls signDirect/signAmino.
sign-gate.ts  export class SignTicket { readonly quote; readonly pressedAt; #sealed } ; export function issueSignTicket(quote, press: {isTrusted:boolean; type:'submit'}): SignTicket — throws unless press.isTrusted && type==='submit' && quote not expired && revision current. The runtime assertion plus the static guard (§3.1) make a ticket impossible to mint outside the review sheet's submit handler.
execute.ts    executeSigned(ticket, keplr, onState): assertNativeStakingAllowed(); if network==='real' assert prefs.realConfirmedAt; reuses runTransaction (lib/transaction.ts) with driver: sign → client.sign(address, msgs, fee, '') → TxRaw.encode; hash → signedTransactionHash (lib/receipt-reconciliation.ts); broadcast → client.broadcastTxSync; confirm → poll client.getTx(hash) ≤ 90 s then verifyStakingReceipt(msgs, tx) (receipt.ts: every expected message type appears once in the tx's events — delegate/unbond/redelegate/withdraw_rewards/proposal_vote with matching validator and amount attributes). Journal transitions in journal.ts.
errors.ts     plainWords(error, action): 'Request rejected|denied|cancel' → 'You stopped this in your wallet. Nothing was sent.'; code 13 /insufficient fee/ → 'The network fee was too low for the chain right now. Review again; the fee is estimated fresh each time.'; code 11 /out of gas/ → 'This needed more gas than estimated. Nothing moved; the fee was charged. Review again (we add 30 % on top of the simulation).'; code 32 /sequence mismatch/ → 'Your wallet sent another transaction a moment ago. Wait for it, then review again.'; code 5 /insufficient funds/ → 'Not enough ZIG for this amount and its fee.'; timeout → 'Still confirming. Check the transaction on the explorer before trying again.' Every message carries the explorer link when a hash exists.
journal.ts    zigoals:staking-journal:v1 (§12); states = lib/transaction-journal.ts's JournalState; max 200 entries, oldest dropped.
prefs.ts      zigoals:staking-prefs:v1 {version:1, network?:'practice'|'real', realConfirmedAt?:ISO, lastValidator?:{[chainId]:valoper}}
```
`lib/app-environment.ts` gains `NATIVE_STAKING_SIGNING_ALLOWED = APP_ENVIRONMENT !== 'INVALID_CONFIGURATION'` and `assertNativeStakingAllowed()`. `FINANCIAL_EXECUTION_ALLOWED` (the Goal Manager contract path) is untouched; the contract path stays testnet-only and undeployed.

### 3.1 How the guard tests enforce the gate
`lib/staking/staking-guard.test.ts` (vitest, static, from the repo root):
1. Files anywhere under `lib/`, `components/`, `app/` that match `/getOfflineSigner|connectWithSigner|broadcastTx|\.sign\(|signDirect|signAmino/` are exactly `['lib/staking/execute.ts','lib/staking/quote.ts','lib/wallet.ts']` (quote.ts only `connectWithSigner` + `simulate`; a second assertion forbids `.sign(` and `broadcast` in quote.ts).

3. `executeSigned(` is called only in `review-sheet.tsx`, after `issueSignTicket`.
4. No file under `lib/ai/**` or `components/ai/**` imports `lib/staking/execute`, `lib/staking/sign-gate`, `lib/staking/quote`, `components/staking/**` or contains `getOfflineSigner`; `lib/ai/actions/staking-prefill.ts` holds no address, key or validator-signer call (regex on `zig1|zigvaloper|sign`).
5. `lib/wallet-guard.test.ts`'s third test changes deliberately: the signer-using files become `['lib/staking/execute.ts','lib/staking/quote.ts','lib/wallet.ts']`, each starting with its assert (`assertFinancialExecutionAllowed` or `assertNativeStakingAllowed`) — equal strength, recorded in STATUS.

## Server routes

- `GET /api/positions?network=MAINNET_READ_ONLY|TESTNET_READ_ONLY&address=zig1…[&minHeight=<digits≤20>]` — egress https://api.zigchain.com or https://testnet-api.zigchain.com only (READ_NETWORKS); existing reader + stZIG by_denom; cache in-memory 60 s per network+address; minHeight bypasses a cached snapshot whose block height is lower; 10 reads/min/client, 120/min/server (unchanged); schema query .strict(): network enum, address publicZigAddress, minHeight optional /^[1-9]\d{0,19}$/; answer {positions: Position[]} max 1000; errors 400/429/502 unchanged; the 403 MAINNET_NOT_ON_PUBLIC_ALPHA branch is removed (C4 lifted for the relay, ADR-028); privacy the relay sees the address (not the person's IP at the LCD operator); documented in PRIVACY.md

- `GET /api/chain/proposals?network=[&id=<digits>]` — egress the same two LCDs: /cosmos/gov/v1/proposals?pagination.reverse=true&pagination.limit=50, /cosmos/gov/v1/proposals/{id}/tally for voting-period ones, /cosmos/gov/v1/params/tallying; cache in-memory 60 s per network(+id); 10/min/client, 120/min/server; schema answer {version:1, network, at, params:{quorum,threshold,vetoThreshold,votingPeriodSeconds}, proposals:[{id, title≤300, summary≤8000, messageTypes:[string], status, submitTime, votingStart, votingEnd, tally:{yes,no,abstain,noWithVeto}, final:boolean}]}; unknown fields dropped; bodies ≤2 MB; privacy no personal data

## Risks

- Mainnet broadcast cannot be exercised by CI or by an agent: every signed path is proven on zig-test-2 with fixtures and by the owner with real Keplr (faucet ZIG); a REAL delegate is the owner's own choice in Gate C, never an agent's. Residual: a mainnet-only difference (fee market, node version) surfaces only then.
- Keplr-in-the-loop gas: the app quotes at the chain minimum 2.5 gazig/gas; Keplr may let the person raise it; if Keplr overrides the fee the signed bytes differ from the quote — the review says so and the receipt check compares messages, not fee.
- api.zigchain.com answers 403 to OPTIONS preflights (R5 LB11): any browser-direct read with a custom header would fail; the design uses only simple GETs browser-direct and the relay for coherent reads. A future WAF change could block the simple GETs too — the fallback is the relay for everything.
- publicnode POST JSON-RPC CORS verified today (OPTIONS 204, ACAO *, allow-headers content-type) but unpublished rate limits and a 24 h data-retention claim only; a change there degrades to 'unavailable', never 0. Solana public RPC limits (100 req/10 s/IP) are respected by one read per wallet per 15 min.
- CoinGecko id drift (zignaly, staked-zig, polygon-ecosystem-token, binancecoin verified live 2026-10-18): a renamed id reads 'unavailable'; the coordinator's catalog guard refuses unknown ids rather than mispricing.
- Keplr Mobile's universal deep link form (https://deeplink.keplr.app/web-browser?url=) is undocumented by example; only keplrwallet:// and intent:// are documented — offer those first and test the universal form on a phone in Gate C.
- Ramp's COSMOS_ATOM asset identifier and hostApiKey referrer binding are inferred/undocumented (R3): confirm in the demo widget before shipping the parameter; otherwise omit it and let the person pick ATOM on Ramp's page. Banxa 'returnUrl' vs 'redirectUrl' naming to be confirmed in sandbox.
- WalletConnect/Reown licence (Community License, 500 MAU / 2.5M RPC thresholds) and the starknet peer dependency of @keplr-wallet/wc-client: Stage 2 is optional and separate; without approval phones keep the in-app-browser path and the honest line.
- Lifting C4 (mainnet reads on the relay) raises upstream LCD calls on the app Worker: existing 10/min/client, 120/min/server limits and 60 s cache cap it; a flood still shows as 429 with the 'try again in a minute' sentence.
- The honesty-label change touches six specs, the hosted verifier's identity stage and the separate landing deployment (landing/index.html, owner-deployed): a mismatch between the app and the landing copy is possible until both are live.
- Testnet unbonding is 21 days (not the registry's 7): an undelegate's completion cannot be observed within the session; the receipt (unbond event + entry) is the evidence, the completion a later owner check.
- Valdora's stZIG rate stays undocumented: Goal Vaults count stZIG in units only; a person expecting ZIG value sees 'stZIG · value in ZIG unavailable (rate not documented by Valdora)'.
- Positions of the connected signing wallet enter the synced platform record (existing tracker path): the owner's 'linked addresses device-only' holds for linked wallets; the connected wallet's address was already synced by the watch-only tracker since Session Z-Cloud — stated in PRIVACY, not changed.
- The Today page has 51 kB of headroom: every Today addition (card balance, vault ring, validator alert line) is inside existing lazy chunks; measured in Gate C before the STATUS entry.
- Unverified-until-Phase-B: mainnet zigchaind version string for REVIEWED_VERSIONS.real (R1 read v5.1.2 on 2026-10-18); re-read node_info application_version before pinning.

## Decisions proposed (see ADR-028 for the recorded ones)

- Native staking signs on the public Alpha: FINANCIAL_EXECUTION_ALLOWED (the Goal Manager contract path) stays as it is and stays off; a separate NATIVE_STAKING_SIGNING_ALLOWED gates only MsgDelegate, MsgUndelegate, MsgBeginRedelegate, MsgWithdrawDelegatorReward and gov MsgVote. ADR-004's 'mainnet is rejected unconditionally' is superseded for these five message types; ADR-009 §6 (flag true only for TESTNET_DEPLOYED) and EARN_DESIGN principle 6 + consent bullet 1 ('the network is testnet') are amended for native staking only; Valdora/stZIG execution stays testnet-first and unbuilt. MANUAL_ALPHA_WORKFLOW line 9 rewritten; PUBLIC_ALPHA_UNDEPLOYED stays the build mode.
- REAL requires an explicit first-time confirmation stored on device (zigoals:staking-prefs:v1 realConfirmedAt); the closest honest version of 'switching to real requires an explicit confirm the first time' given no accounts: per device, per account scope, reset by the account's erase.
- Session Z-Cloud C4 is lifted for the relay only: /api/positions reads mainnet on public builds because a coherent block-height read is impossible browser-direct (api.zigchain.com 403s OPTIONS preflights); the relay's limits and cache stand; the browser reaches api.zigchain.com only with simple GETs (balance by_denom) and rpc.zigchain.com for signing.
- Only Keplr signs ZIGChain (R4): 'any other wallet R4 proved can sign' resolves to Ledger through Keplr's amino signer; Leap and Cosmostation remain ended/link-only; OKX/Trust custom-Cosmos support is unverified, so they are read-only EVM links. The owner's 'Ledger via WalletConnect' becomes Ledger via Keplr today and Ledger Wallet address linking over WalletConnect in Stage 2.
- Gas price steps for Keplr chain suggestions follow Keplr's registry (low 2.5 gazig, average 25, high 50) for both networks (the app's old 2.5/2.5/4 suggestion is replaced); the app's own fee quote uses the chain minimum 2.5 gazig/gas × simulated gas × 1.3 and tells the person their wallet may raise it.
- Keplr connect order: enable(chainId) first (both chains are in Keplr's registry: cosmos/zigchain.json and cosmos/zig-test.json, read 2026-10-18), experimentalSuggestChain only on the 'no chain info' error.
- Claim-all is one signature carrying N MsgWithdrawDelegatorReward, every validator listed on the review screen — an amendment to EARN principle 3's 'no batching' for this one case; the rewards sweep is one MsgDelegate (the chain auto-claims on delegate), so no batching there.
- Later options, recorded not built: authz auto-compound (no REStake operator on ZIGChain, CosmJS 0.38 has no authz amino, conflicts with principle 3), feegrant (ZIGoals would hold a funded key), memo attestations and pacts (privacy review / contract), the grants-and-allowances panel (nothing to show yet).
- zigoals:linked-wallets:v1 is kept, not versioned to v2: the loose schema already keeps unknown fields and hides unknown kinds in AE's build, so 'chains', 'via' and kind 'solana' are additive; max 12, Export, never synced, never restored, unchanged.
- Linked-wallet balances and Goal Vault links are device-only records and never enter the synced platform record; the connected signing wallet's ZIGChain observations keep using the existing synced tracker path (watchScope) so Today, Wealth, Goals allocations and the staking card update as they do now.
- Balance reads: ZIGChain through the relay (address seen by ZIGoals' Worker, not the person's IP by the LCD); Cosmos Hub, Ethereum, Arbitrum, Base, Optimism, Polygon, BNB and Solana browser-direct to publicnode.com, Bitcoin to mempool.space (addresses seen by those operators, never by ZIGoals) — R4's privacy decision; each named in PRIVACY.md with the operator's retention claim and its date.
- Tokens tracked are a fixed registry: native coin per chain plus Circle USDC (Ethereum, Arbitrum, Base, OP Mainnet, Polygon PoS, Solana); no BNB USDC (Circle lists none); Polygon's native is POL (CoinGecko polygon-ecosystem-token). No token discovery from user input.
- Pricing stays on the market coordinator with existing CoinGecko ids (ethereum, binancecoin, polygon-ecosystem-token, solana, bitcoin, cosmos, usd-coin, zignaly, staked-zig), one deduplicated ≤32-pair chunk per page refresh; practice balances are never priced; 'unavailable' with the reason, never 0.
- ZIG is identified by base denom 'azig' only; the same-name decoy 'coin.zig153u6vhv4ds6x95chdnqmsduwxzpt0teh43alsk.zig' (symbol ZIG, exponent 6) and any other symbol-ZIG denom are shown as look-alike tokens with a warning; no message builder takes a denom.
- On-ramps are Ramp Network and Banxa (R3), redirect only (hosted page / referral URL), never an iframe (the app's Permissions-Policy denies the camera on /app and KYC needs it); public identifiers live in apps/web/config/onramps.json, empty by default; day one offers the plain official sites; the only route offered is ATOM to the person's own cosmos1 address (no on-ramp sells ZIG on ZIGChain, checked 2026-10-18), then guided IBC (channel-1555 → channel-4) and OroSwap.
- The 'Add money' address is only ever a Keplr-held cosmos1 derived from the connected/linked zig1 (same key, coinType 118); typed addresses are never put in a provider URL ('never links built from user input'); provider URLs' origin and path come from the verified link registry.
- One verified link registry (lib/links/registry.ts) with a 'verified link · date' mark for every outgoing link this lane adds; a test forbids https literals outside it; explorer links go through buildExplorerUrl with mainnet zigscan/range entries (lastVerified 2026-10-18).
- Governance votes use /cosmos.gov.v1beta1.MsgVote for both direct and amino signers (CosmJS 0.38.1 has the v1beta1 amino converter, not v1); eligibility is shown from the person's bonded delegations; the app keeps its own vote journal because votes leave chain state at tally.
- Governance is a new hideable route /app/governance in the Staking nav group with its own budget line; Add money is /app/wealth/add-money with its own line; existing budgets are never raised and every new piece is a lazy chunk.
- ZIGi gets a prefill-staking card (PREFILL kind, plain fields, sessionStorage hand-off) — a policy change to ZIGI_ACTIONS_Z's 'stake… no' row, limited to pre-filling the form; the gate and the static guard keep every ZIGi path away from signing.
- The public-safety sentence changes from 'Simulation + wallet connection only. No blockchain transactions or financial signatures.' to 'Staking and votes sign in your own wallet (practice or real, your choice). Nothing else moves, and ZIGoals never holds keys.' in the app, the About panel, Help's Known limitations, the hosted verifier's expectations and the landing page (owner-deployed separately).
- Projections appear only as labelled illustrations (EARN principle 4 amended as the prompt asks): the person's own APR assumption or 'today's chain rate' derived from annual_provisions ÷ bonded_tokens with community tax and commission, with source URL and 'as of block N'; never summed into progress or ranked.
- WalletConnect/Reown is Stage 2: dormant until the owner pastes reownProjectId into apps/web/config/wallets.json and approves the dependency (@walletconnect/sign-client 2.26.0 under the WalletConnect Community License, 500 MAU / 2.5M RPC thresholds); @keplr-wallet/wc-client is not adopted (starknet peer dependency); its three Cosmos RPC methods are called on sign-client directly; the CSP hosts are added in that same commit and asserted present iff the id is set.
- Test-assertion changes, all equal strength and listed in STATUS: wallet-guard's signer-file list (one → three files, each behind its assert); public-safety's connect-src exact list; (Stage 2 only) 'no wss' narrowed to the two relay hosts; the six honesty-label specs and the verifier's identity texts.
- Server routes follow the positions-relay pattern exactly (force-dynamic, no-store, strict query, in-memory 60 s cache, 10/min/client, 120/min/server, egress only to the two LCDs) — no new Worker, binding or secret; the market coordinator Worker is untouched.
