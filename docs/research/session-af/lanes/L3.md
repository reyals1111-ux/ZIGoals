## 1. Storage (TIER 3 storage / data formats)

### 1.1 Keys — `lib/af-device-keys.ts` (no imports)
```ts
export const CHECKLIST_KEY = 'zigoals:checklist:v1';        // favourites, custom items, sections, order, per-item defaults
export const CHECKLIST_DAYS_KEY = 'zigoals:checklist-days:v1'; // the day history and today's tick receipts
export const AF_PERSONAL_KEYS: readonly string[] = [CHECKLIST_KEY, CHECKLIST_DAYS_KEY];
```
Display preferences go into the existing loose `zigoals:ui-prefs:v1` (`lib/ui-prefs/schema.ts`) as a new optional group `checklist: z.looseObject({launcher?: boolean, folded?: boolean, view?: 'path'|'list' (string ≤12), accent?: string ≤24, sounds?: boolean, haptics?: boolean, nudges?: boolean})` — the pattern of `musicFolded` and `today`. Older builds keep the unknown field (loose object), so no new display key is needed.

### 1.2 `zigoals:checklist:v1` — `lib/checklist/schema.ts` (`z.looseObject`, `version: z.literal(1)`)
```json
{"version":1,
 "items":[{"id":"ck_<uuid>","kind":"habit","ref":{"habitId":"<habit id>"},"section":"morning","addedAt":"2026-10-18T07:00:00.000Z"},
          {"id":"ck_…","kind":"goal-step","ref":{"goalId":"12","milestoneId":"<id>"},"section":"anytime","addedAt":"…"},
          {"id":"ck_…","kind":"custom","label":"Play piano 15 minutes","colour":"gold","section":"evening","addedAt":"…"}],
 "healthItems":[{"id":"ck_…","kind":"health","input":"water","defaultValue":500,"unit":"ml","lastValue":500,"section":"morning","addedAt":"…"},
                {"id":"ck_…","kind":"health","input":"diary","ref":{"sourceKind":"food","sourceId":"health_…"},"defaultValue":1000,"section":"morning","addedAt":"…"},
                {"id":"ck_…","kind":"health","input":"weight","lastValue":78000,"unit":"g","section":"morning","addedAt":"…"},
                {"id":"ck_…","kind":"health","input":"sleep|meditation|fast","defaultValue":10,"section":"evening","addedAt":"…"}],
 "sections":[{"id":"morning","label":"Morning orbit","colour":"cyan"},{"id":"afternoon","label":"Afternoon orbit","colour":"blue"},{"id":"evening","label":"Evening orbit","colour":"purple"},{"id":"anytime","label":"Anytime","colour":"pink"}],
 "order":["ck_…","ck_…"]}
```
Limits: ≤ 60 items + ≤ 40 health items, label ≤ 60, ≤ 12 sections, section labels ≤ 30, colour from `PATH_COLOURS` ids (unknown kept, shown as the item's default). `kind`/`input` are strings in the schema with a known-set filter at read time, so a newer build's kind survives a write here and is left out of the path (the `linked-wallets` rule). Why two arrays: health favourites describe Health use; when the record rides extras sync later it goes in the `life` section with `healthItems` listed in `deviceFields` (the `GOAL_EXTRAS dormant` mechanism in `lib/vault/extras-sections.ts`), so Health-describing favourites never travel outside the Health consent. In Session AF both keys are **never synced** (guard test like `linked-wallets.test.ts`).

### 1.3 `zigoals:checklist-days:v1`
```json
{"version":1,
 "days":{"2026-10-17":{"total":6,"done":6,"perfect":true},"2026-10-16":{"total":6,"done":4,"perfect":false}},
 "today":{"date":"2026-10-18","ticks":[{"id":"ck_…","at":"2026-10-18T06:58:12.000Z","record":{"kind":"water","id":"health_water-…"}}],"custom":["ck_…"],"nudged":["10","15"]}}
```
`days` holds counts only (≤ 400 entries, oldest pruned), `today` holds the receipts of ticks made on the path (item id, instant, the record id the tick created) and the custom ticks. Receipts are the only Health-adjacent content; for a later sync `today` is a `deviceFields` entry and `days` travels. Sealing: the first read on a new day moves yesterday's derived summary into `days[yesterday]` (idempotent, `sealDay()` in `lib/checklist/day.ts`); a day with zero favourites is not written (neutral).

### 1.4 Readers for older builds and the frozen check
Both records are loose and versioned; releases #37–#43 have no module for them, so the frozen reader reports ABSENT (ignored, bytes kept) — exactly the linked-wallets case. `lib/vault/frozen-fixtures.test.ts` gets `records[CHECKLIST_KEY]`, `records[CHECKLIST_DAYS_KEY]`, two `checks.push({key, module:'./checklist/schema', spec:'CHECKLIST'|'CHECKLIST_DAYS', expect:{...}})` and the assertion becomes `[...carried, GOAL_EXTRAS_KEY, LINKED_WALLETS_KEY, CHECKLIST_KEY, CHECKLIST_DAYS_KEY].sort()`; `node scripts/frozen-readers.mjs --out docs/verification/session-af/gate-c-frozen-readers.txt`. Registries: `DEVICE_RECORD_KEYS` (`...AF_PERSONAL_KEYS`), `DEVICE_KEYS.checklist/.checklistDays`, `DEVICE_LABELS` (`['Checklist favourites and custom items', 'Checklist']`, `['Checklist day history', 'Checklist']`), `forgetAaDeviceRecords` erase list, PRIVACY paragraph, THREAT_MODEL table, `docs/product/CHECKLIST.md`.

### 1.5 Today layout id (TIER 3 storage)
`today:checklist` joins Today's `main` region (`components/dashboard/today-dashboard.tsx` `LayoutRegion region="main"`), after Today's focus. `lib/page-layout.ts` `resolveOrder` ignores unknown saved ids and keeps them on save, as `habits:routines` proved in AE (frozen fixture `layout.added`): the fixture gains `today:checklist` in a Today `main` order with the older ids listed.

## 2. The shared path engine (`lib/path/`, `components/path/`)

### 2.1 Model — `lib/path/model.ts` (pure, no React)
```ts
export type PathColour = 'teal'|'blue'|'magenta'|'purple'|'gold'|'pink'|'cyan';
export type StepState = 'done'|'undone'|'locked'|'running';
export type PathStep = {id: string; label: string; note?: string; colour: PathColour; state: StepState; glyph?: string; href?: string; value?: {current: number|null; unit: string; suggested: number; min: number; max: number; step: number}; done?: {at: string}};
export type PathSection = {id: string; label: string; colour: PathColour; steps: PathStep[]};
export type PathMilestone = {id: string; at: 'half'|'end'|{afterStep: string}; label: string; reached: boolean; reward?: {badge?: string; xp?: number}};
export type PathModel = {id: string; sections: PathSection[]; milestones: PathMilestone[]; zigi?: {state: string; near: string|null}; progress: {done: number; total: number}};
export const pathProgress = (sections) => ({done, total});           // locked steps are not counted
export const nextStep = (model) => PathStep|null;                      // first undone in order
export const litSegments = (section) => boolean[];                     // segment i lit when steps i and i+1 are done
export const milestoneState = (model) => PathMilestone[] with reached;   // half = done ≥ ceil(total/2)
export const flatten = (model) => PathStep[] in path order;
```
`lib/path/colours.ts`: `PATH_COLOURS: Record<PathColour, {label, token}>` → `teal: var(--nebula-flow start #18d9ef)`, `blue: var(--brand-blue,#459dff)`, `magenta: var(--brand-magenta,#f06dff)`, `purple: var(--pillar-goals,#9273ff)`, `gold: var(--pillar-wealth,#ffd27a)`, `pink: var(--pillar-health,#ff74be)`, `cyan: var(--pillar-habits,#23eaff)` (tokens from `app/visual-v21.css`). The Earn lane's "Start here" path uses `locked` + `href` steps and `at: {afterStep}` milestones; the Academy mini path is one section of lesson steps. Both consume `<Path>` unchanged.

### 2.2 Renderer — `components/path/path.tsx`
```tsx
<Path model={model} layout="snake"|"straight" density="full"|"compact"
      onStep={(step, intent: 'tick'|'open'|'value') => void}
      renderValue={(step, commit) => ReactNode}          // the Checklist's stepper
      zigi={<PathZigi/>} ariaLabel="Today's path"/>
```
DOM: `<div class="path-stage" data-layout>` → per section `<section class="path-section" data-colour>` with `<header class="path-banner">` (a coloured glass band: eyebrow, label, "2 of 3") → `<ol class="path-steps">` → `<li class="path-step" data-state data-side="l|r">` holding `<button class="path-dot" aria-pressed={done} aria-label="{label}: {state}">` (72 px desktop, 64 px phone; always ≥ 44 px) and `<span class="path-label">` (16 px, 15 px phone). One `<svg class="path-line" aria-hidden>` per section, absolutely over the list, draws cubic segments dot-centre to dot-centre (`use-path-geometry.ts`: centres from `getBoundingClientRect` on mount, `ResizeObserver` and font load; never per frame — the footer-path rule). Snake layout alternates dots ±18 % of the column width (desktop) and ±12 % (phone), straight layout centres them. Lit segment: stroke `url(#path-neon)` (`#9273ff 0 → #23eaff .45 → #ff74be .8 → #f06dff 1`, the footer's main line), 3 px + a 9 px blurred glow twin; unlit: `color-mix(in srgb, var(--line) 70%, transparent)` 2 px. Milestones render as `<li class="path-chest" data-reached>` with a `GlassRing` and a lid glyph; the ZIGi anchor renders as `<li class="path-zigi">` placed before `nextStep`.

Motion (all one-time, transform/opacity/stroke only): the dot fill (`scale .92→1`, 320 ms), a ring burst (`.path-burst`, 520 ms, `motion-glide`), the segment lights by `stroke-dashoffset` (420 ms) when both ends are done, the chest lid opens once per reach (`sessionStorage`-free: keyed by the celebration seen map). Reduced motion / Motion Off: `[data-state]` paints the final still at once; `:root[data-app-motion=off] .path-stage *{animation:none!important;transition:none!important}`. Keyboard: dots are buttons in DOM order; `Home/End` jump; the "Jump to next" bubble is a button that scrolls `nextStep` into view and focuses it.

### 3.3 Dot state is derived from the real record (`lib/checklist/derive.ts`)
| Item | Done when | Colour |

### 3.4 Record adapters (`lib/checklist/adapters.ts`) — every write goes through the page's own mutator; every tick returns an `undo`
| Kind | Apply | Undo |
|---|---|---|
| habit boolean/build | `habits.smartDone(id, habitsDay)` (`logHabitValue(…, smartDoneValue(rule))`) | `habits.setValue(id, habitsDay, previous.count, previous.note)` |
| habit count/duration | stepper → `habits.addValue(id, habitsDay, value)` | `setValue` to the previous count |
| habit quit/limit | `smartDone` logs 0 = "stayed clear"; the stepper logs the count for limit habits | previous count |
| goal-step | `platform.update(s => withMilestones(s, goalId, list => …done:true))` (`goal-milestones.tsx:28` helper exported) | `done:false` |
| water | `health.update(latest => addWater(latest, {id, date: healthDay, amountMilli, unit}, at))` (`today-focus.tsx:48` shape) | `removeWater(latest, id)` |
| weight | `saveWeight(data, {id, date: healthDay, grams}, at)` (upsert; the previous weight for the date is captured) | `removeHealthItem('weights', id)` or restore the previous |
| diary/supplement | `logHealthItem(data, {id, sourceId, sourceKind, date, meal, quantityMilli}, at)` | `removeHealthItem('diary', id)` |
| sleep dot | no night running → `startNight(s, now, zone)`; running → `endNight(s, id, now)` (the `sleep-tonight.tsx` calls) | start: `deleteNight(s, id)`; end: `saveNight` back to `end: null` is not a mutator → undo = reopen through `deleteNight` + `startNight` with the original start (documented) |

Errors from a mutator (not scheduled today, Health locked, storage refused) surface as the page's own message text under the dot and the dot stays undone.

### 3.5 Day boundary (`lib/checklist/day.ts`)
`checklistDay(now) = zonedDay(journalTimeZone() ?? deviceTimeZone(), now)` (the Intl `formatToParts` body of `habitCalendarDay`). `useChecklistDay()` re-evaluates on `everyHalfMinute`, `focus`, `visibilitychange` and the journal zone's `useJournalZone()`; when the day changes, `sealDay(record, previous, summary)` writes yesterday's `{total, done, perfect}` and clears `today`. Adapters write with their module's day (`habitCalendarDay(habits.data)`, `healthDay(preferences.timezone)`); when a module's own zone makes that day differ from the Checklist day the dot's note says "logged for {date}". No day-start hour exists in the app, so "local midnight in your journal time zone" is the rule, said once in Options.

### 3.6 Streaks, fairness, freezes (`lib/checklist/streak.ts`)
Streak = consecutive sealed days with `done === total > 0`, plus today once complete; sealed days with `total === 0` are skipped, not broken; the time of the last tick is irrelevant (ticking at 23:59 counts). Perfect orbit = today's receipts cover every counted dot and their order equals the path order (a dot done elsewhere has no receipt → "Done, order unknown", never a punishment). A missed day can be mended with an earned freeze when the game layer is on: the day's missed favourite habits are listed and one is repaired through `applyFreeze(habits, habitId, date, today)` (the real mechanism, so `freezesUsed` stays derived); the Checklist day then reads as frozen (`days[date].done === total` is not rewritten; `streak.ts` treats a day whose missed habits all carry the `FREEZE_NOTE` skip as kept). A missed day without habit favourites has nothing a freeze can repair, and the UI says so.

### 3.7 Rewards, badges, XP, celebrations (game layer on only)
`GameStores` gains `checklist?: ChecklistDays | null` (additive). `xpEvents`: `checklist:{date}` 15 XP for a sealed or current day with `done === total > 0`, +5 for `perfect` (`XP_RULES.checklistDay`, `checklistPerfect`). `BADGES` gains `first-orbit` ("First orbit", a day with every dot lit), `seven-orbits` ("Seven orbits", seven such days), `perfect-orbit` ("Perfect orbit", a day in path order). Chests: `milestones: [{at:'half', reward:{xp: 0}}, {at:'end', reward:{badge:'first-orbit'}}]`; reaching one is a `Celebration` (`kind:'checklist'`, id `checklist:half|all:{date}`) through `pendingCelebrations` and the one renderer; the chest lid animates once because the seen map remembers it. With the game layer off, the chests still open (a sparkle, no badge/XP line).

### 3.8 ZIGi on the path
`<PathZigi>` renders `<ZigiFigure state>` beside `nextStep` ("pointing": a small nebula arrow from the figure to the dot), `encouraging` at rest, `celebrate` for 1.6 s after a tick, `proud` at half, `celebrate` at all done, `sleepy` after 22:00 local; stills under reduced motion. Signals: `checklist_tick`, `checklist_half`, `checklist_complete` (validated). Command surface exposed for the ZIGi lane (`lib/checklist/commands.ts`): `checklistSummary(record, days, derived)` → `{date, total, done, next, items:[{label, kind, done}]}` for a read tool `checklist_today` (area `habits`, refusal when the Checklist is empty); `findItemByName(record, words)`; and `OPEN_PAGES` gains `'checklist'` (`lib/ai/actions/schema.ts:82`, the `open-page` card). Ticks by voice map to the kinds that already exist (`check-in`, `log-water`, `log-weight`, `log-meditation`, `start-night`/`end-night`, `start-fast`/`stop-fast`); only custom items need a new card kind `tick-custom` — proposed to the ZIGi lane, not added here.

## 6. Data flow (one tick)

## Risks

- Shell weight: the launcher, registrar, More row and dock CSS ship on every page; the smallest headroom is Goals (43.6 kB) and Markets (45.7 kB). Keep the shell addition ≤ 4 kB gzip (glyph inline, no chunk) and measure before the budgets commit; if over, lazy-load the registrar's nav entry and the badge logic.
- Today's 51 kB headroom: the Today card must be a lazy chunk with one DOM root (a Fragment root silently drops a layout item — memory note); never import the path engine on Today.
- The synced `pages` record cannot take a new button id (zod partialRecord unrecognized_keys → #37–#43 refuse the whole settings v3 record); the device-only switch is the only safe form, and the owner may want the synced wording — ADR row.
- Receipt/truth divergence: a dot done on its own page has no receipt, so Perfect orbit cannot be judged; copy must say 'order unknown' rather than fail the person.
- Day-zone mismatch: a Habits or Health zone override can make a module's day differ from the journal day; the dot note shows the written date, but a tick near midnight can land on 'yesterday' from the Checklist's view — documented, not hidden.
- saveWeight upserts by date: Undo must restore the previous weight for that date, not just remove the new one.
- Sleep undo: no mutator reopens an ended night; Undo = deleteNight + startNight with the original start (a new id). Document in the adapter and the Help answer.
- navigator.vibrate is absent on iOS Safari and may be throttled by Chrome without a user activation; the helper never throws and Options reports availability honestly.
- Theme generator: new CSS must either be islands (identical colours) or accept OKLCH remapping; forgetting an island makes Light recolour the dots — the themes spec catches it; regenerate light.css/dark.css and the hashes in the same commit or CI's --check fails.
- Hosted verifier stage insertion renumbers landing/recipe; docs/deployment/MANUAL_ALPHA_WORKFLOW.md and HOSTED_SMOKE.json consumers must follow; stage 7 must leave the shared page on a route stage 8/9 can start from (landing opens its own page).
- Shared registries (whats-new.ts, help-page.tsx, static.ts, ADR-028, STATUS, OPEN_PAGES, golden set) are edited by several AF lanes: follow the lane lock rule (H3) — one lane bumps WHATS_NEW_RELEASE and the AF Help section skeleton; the others add rows.
- XP/badges from a device-only record: a second device shows less XP until the days record syncs (not in AF) — stated in Known limitations and ADR.
- Drag reorder on touch must not fight page scroll (touch-action: none on the handle only) and must have the keyboard/tap alternative (Structured ships no drag on web).

## Decisions proposed (see ADR-028 for the recorded ones)

- The Checklist launcher's Settings switch is device-only (ui-prefs.checklist.launcher), not a new id in the synced `pages` record: zod 4.6.5 partialRecord over an enum reports unrecognized_keys, so a new BUTTON_IDS entry would make releases #37–#43 refuse the whole strict settings v3 record on rollback. Closest honest version of 'optional in Settings': a switch beside Your pages & buttons labelled 'on this device'.
- The Checklist day boundary is local midnight in the journal time zone (settings journalTimeZone, else the device zone): no day-start hour exists anywhere in the app (grep confirmed), so 'respect any existing day-start setting' means the journal zone; adapters write with their module's own day (Habits' zone override, Health's preferences.timezone) and the dot says when that date differs.
- Dot state is derived from the real record (habit day status, milestone done, a night ended today, a session today, a fast today) with receipts only for order/undo/custom and for value entries (water/weight/diary, truth-checked against the record id); the record is the truth and a tick made elsewhere lights the dot.
- 'Full-screen' is honoured as a full-bleed page inside the app shell: the sidebar/phone chrome and the Alpha notice stay because the shell carries the public-safety labels (TIER 3 public-safety) and navigation; a chrome-less mode would hide them.
- Phones get no third floating button (ADR-019: ZIGi is the one floating button on a phone); the Checklist is reached from More, the Today card and a Home Screen shortcut; the top-bar button is not added (the owner's wording was 'top bar or More').
- Vitamins/supplements have no log of their own (amounts derive from the diary, lib/health-vitamins/schema.ts): a 'vitamins' dot is a starred familiar food or pinned item logged to the diary; the Help answer says so.
- A goal favourite is a goal step (an open milestone); a goal without open milestones gets one 'Open goal' dot that is not counted — the Checklist never records money (contributions stay on the goal's own form).
- Streak freezes are the game layer's real mechanism (applyFreeze on a missed favourite habit, FREEZE_NOTE skip), never a Checklist-only flag, so freezesUsed stays derived; a missed day with no habit favourites cannot be frozen and the UI says why.
- XP, badges and celebrations for the Checklist derive from zigoals:checklist-days:v1 (counts only) with nothing new stored in the game record; because that key is device-only in AF, a second device shows less XP until a later sync — recorded as a known limitation, not hidden.
- Sounds default off and are Web Audio bells made on the device (no file, no CSP change), gated by the reminders plan's quiet hours; vibration uses navigator.vibrate where it exists (none on iOS Safari) and is reported as unavailable rather than faked.
- Both new keys are never synced in AF (guard test) and are shaped for later extras sync: healthItems and today receipts are the deviceFields that must never travel outside the Health consent; the owner decides the sync home later.
- The hosted verifier's Checklist stage is number 7 (landing → 8, recipe → 9) so the local order spec covers it on one page; its fictional habit is a sentinel that must never appear in any request record.
- The only animation loop on the page is the Nebula mist drift (transform only), owner-approved as the background; every other motion is one-time and every state is a still under reduced motion and Motion Off.
- The ZIGi command surface for the Checklist is read + open only from this lane (checklist_today tool data, OPEN_PAGES 'checklist'); a 'tick-custom' card kind is proposed to the ZIGi lane, and ticks by voice reuse the existing check-in/log-* kinds.
- The path engine's data model is owned by this lane (lib/path/model.ts, components/path/); the Earn lane consumes locked/href steps and afterStep milestones without changing the renderer; any change to the model's shape is a cross-lane change under the lock rule.
