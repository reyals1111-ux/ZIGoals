## 9. recipe-import DNS-rebinding exposure
`lib/server/recipe-import.ts checkRecipeUrl`: https only, no user-info, port 443 only, hostname must contain a dot and not match `PRIVATE_HOST = /^(localhost|.*\.(local|localhost|internal|home|lan|test|invalid|example))$|^[0-9.]+$|^\[?[0-9a-f:]*:[0-9a-f:]*\]?$/i`; `fetchRecipePage`: `redirect:'manual'` (3xx → REDIRECT), 8 s, 1 MB streamed cap, text/html | application/ld+json | application/xhtml+xml only, fixed UA, no credentials; route: 10/min/client, 60/min/server, 429 with Retry-After 60. Exposure: the check is by name only; a public hostname that resolves to a private/link-local address (or changes between resolution and connection) is accepted and fetched by the Worker. Mitigations present: no redirects, port 443 only, content-type and JSON-LD-only parsing, bounded size. `wrangler.alpha.jsonc` sets compatibility flag `global_fetch_strictly_public` — its exact semantics are not stated in the repo; verify at Cloudflare's compatibility-flags documentation before relying on it. A resolve-then-pin inside a Worker would need: (a) an explicit DNS step (e.g. DNS-over-HTTPS — a new server-side egress origin, to be added to the egress policy's server-only list, not connect-src), (b) rejecting any A/AAAA in private/loopback/link-local/ULA ranges, (c) making the HTTP connection use the checked address — Workers' `fetch()` offers no IP pin for arbitrary hosts, so this would mean a raw TLS connection (`cloudflare:sockets` connect() to the IP with the hostname as SNI) and a hand-written HTTP/1.1 client, or accepting a residual TOCTOU window; (d) keeping all current limits. Unknown: whether Cloudflare's runtime already blocks private-range fetches on this account (not verifiable from the repo).
