# Bounded account integration review
- Scope: changes since 8d998b0 in the private-account adapter, durable session registry, device UI, backup fences, account transport and sync coordinator; apply/journal/local-outbox dependencies were read for race reasoning. This is not a full security or cryptographic audit.
- Relevant specifications read: AUTH-01–12, ENC-01–10 and SYN-01–16; findings concentrate on AUTH-06/07, ENC-05/07/09 and SYN-03/09.
- Corrected P2 (source rechecked): private-account.ts:47/49 now preserves cookies and returns 503 for provider/registry non-auth failures, clearing only on 401/403. New owner regression covers 429/500/503/507; this review inspected the assertion but did not rerun it.
- Corrected P2 (source rechecked): vault-sync-controls.tsx:39 now fences after the final awaited outbox acknowledgement before publishing success or enabling automatic sync. Captured outbox deletion remains scoped to its original account; deterministic race injection remains acceptance work.
- Session expiry limitation: sessions.mjs:14/18 records active:true without expiry and lists all unrevoked registrations as active. Provider validation still denies expired tokens, but the device list can misdescribe expired access and lifetime registration count eventually reaches 5000. Track verified expiry or label registrations honestly; define retention before claiming complete session lifecycle support.
- Positive source checks: worker derives tenant from verified provider identity, overwrites caller token-hash headers, compares captured account identity and validates vault identity; revocation is rechecked inside the same storage transaction as vault writes.
- Registry rejects re-registration of a revoked token hash. Session operations select only that authenticated tenant’s durable object; device labels are bounded strings rendered as text. Token hashes, labels and sign-in times remain server metadata.
- Backup preparation captures storage identity and account generation around exports and encryption; account-change clears generated secret/preview; decrypted preview checks generation before publication. Restore delegates to storage-scoped import with existing recovery copies.
- Outbox acknowledgement captures operation IDs before data capture and deletes only those IDs after server acknowledgement, local apply and journal commit. Writes arriving later are not in that captured list and remain pending.
- Local apply checks captured/current data under each domain lock and validates before commit; finance remains one aggregate. Multi-domain apply and journal are separate transactions, so interruption can require retry or conflict review; this is not all-domain atomic restore/sync.
- No duplicate suites were run for this review. Existing adapter/registry and two-profile browser results were reported by the integration owner; source/test inspection here does not independently re-certify those runs.
- Remaining: deterministic apply/journal/acknowledgement interruption, expired-registration metadata/retention, full-domain offline/conflict/recovery and hosted/physical acceptance. AccountDevices checks 1 MB only after await res.text(); server reads are bounded, but the browser lacks a streaming response cap.
- Review only: no production/test files changed in this review pass. Earlier widget/status work has separate WIDGET_STATUS_EVIDENCE.md and was frozen before this pass.
