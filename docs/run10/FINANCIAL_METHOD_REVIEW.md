# Independent financial method review

Review scope: the Run10 manual financial evidence ledger, exact-boundary cumulative time-weighted return (TWR), dated manual FX, completeness review and immutable sync transition. Reviewer did not author the financial model/UI. This is bounded source and fixture verification, not financial certification, a GIPS compliance assessment or hosted acceptance.
Primary reference: [CFA Institute, GIPS Standards Handbook for Firms](https://www.gipsstandards.org/standards/gips-standards-for-firms/gips-standards-handbook-for-firms/), Provision 2.A.24 discussion of true TWR and external-flow valuations, and Provision 4.B.2 cumulative-return example. The supported method requires complete valuations immediately before and after each external flow, then geometrically links subperiod returns. It does not infer valuations or claim money-weighted return/XIRR support.
Formula reviewed: cumulative TWR = product(closing value before each flow / opening value after the previous flow) × (final boundary / last post-flow opening) − 1. Each post-flow value must equal its immediately preceding value plus the signed external flow. Exact integer/rational factors are reduced and cross-canceled before multiplication; only displayed percentages round half-up to eight decimal places. Subperiod display rounding never feeds cumulative linking; income and fees remain included in supplied valuations rather than added again.
Sources read: [financial-events.ts](../../apps/web/lib/financial-events.ts) in full, [financial-events.test.ts](../../apps/web/lib/financial-events.test.ts) in full, [financial-evidence.tsx](../../apps/web/components/platform/financial-evidence.tsx), the relevant schema/append-only validation in [positions.ts](../../apps/web/lib/positions.ts), the platform update path, [account-data.ts](../../apps/web/lib/vault/account-data.ts), and exact FIN-01 through FIN-15 specifications in [REQUIREMENTS.json](REQUIREMENTS.json). Financial event references to contributions/revisions provide provenance; this calculator does not automatically reinterpret contributions as external flows or calculate their plan performance.

Reviewed start 10000 and end 11000 at two decimal places returned 10%; replacing the same end record with 999000 incorrectly retained review and returned 9890%. Final `financialEvidenceBasis` (financial-events.ts lines 80–106 at review) binds canonical portfolio, selected-period original/correction event content and referenced FX. Legacy ID-only reviews require review again. UI confirmations capture and recheck that basis inside the update callback.

The original reviewed two-subperiod fixture remains 21%. This was an additional read-only in-memory check; the checked-in same-ID regression initially covered event/portfolio mutation.
Corrected finding 2 — synchronous arithmetic: a valid 200-flow fixture with 71-digit amounts originally took 12.342 seconds in `evaluateTwr`, called during rendering. Fixture start = 10^70; each flow i is an inflow of 1, pre-flow value = 10^70 + (4i + 1), post-flow value = pre-flow + 1; final value = 10^70 + 997. Flows occupy consecutive days after 2020-01-01, ending before 2021-01-01; all amounts use two decimal places/USD. Final implementation cross-cancels individual/cross factors, indexes evidence references and memoizes UI evaluation. An explicit 8,000 normalized-valuation-digit work limit returns `CALCULATION_BOUND` before rational linking; no approximation or relaxed financial eligibility substitutes for the calculation.
Independent arithmetic recheck: the original 200-flow stress fixture now returns `CALCULATION_BOUND` in 0.82 ms; a reviewed 25-flow variant with the same 71-digit construction remains available in 1.13 ms. These are single local correctness/timing observations on the pinned runtime, not a production benchmark or general device latency guarantee.
Corrected sync boundary: final `validateData(after, before)` in account-data.ts lines 13–23 checks retained immutable financial evidence before applying sync. Existing statement rows/reviews and relevant contribution, valuation, history, asset-event, plan-revision and lifecycle records cannot be silently replaced or removed. Explicit backup replacement remains a separate path; content-bound reviews independently prevent stale approval after changed imported evidence.
Focused independent verification: Node 24.19.0 / pnpm 11.19.0; `pnpm --filter @zigoals/web exec vitest run lib/financial-events.test.ts lib/vault/final-safety-review.test.ts` passed 16 tests across two files in 354 ms. Financial fixtures include deposits, withdrawals, loss, unsafe-Number-scale values, missing/mismatched boundaries, simultaneous/endpoint flows, zero capital, void corrections, dated FX mismatch and stale reviews. `git diff --check` was clean at this checkpoint. No FIN implementation files were edited by the reviewer.
Reference fixture: the handbook's factors [1.023, 0.953, 1.069, 1.032, 1.009, 0.969] geometrically link to 5.15765192% at eight decimals, agreeing with its 5.2% one-decimal example. The separate deposit fixture 100 → 110; deposit 50; 160 → 176 yields 21%. The withdrawal fixture 100 → 90; withdraw 50; 40 → 44 yields −1%. No annualization or return estimate from net wealth change is introduced.
Supported limits remain explicit: one portfolio currency; manually retained complete statement evidence; positive opening/post-flow capital; unambiguous flow instants; no unresolved transfers, quantity corrections or unclassified events; no inferred FX; at most 200 flow boundaries, 8,000 normalized valuation digits and a 64KB stored review basis. Wider portfolio provenance/completeness, historical import, financial analytics and every FIN requirement are not established by these tests. Full browser/device/hosted sync acceptance and financial certification were outside this independent review. No remaining material formula defect was identified within the inspected supported method.
