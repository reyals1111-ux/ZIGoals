# Run #10 operating and compatibility policy

Draft implementation only. Public Alpha, chain execution and live infrastructure are unchanged. All local verification uses fictional private records; hosted email and physical phone acceptance are not established.

- Identity: Supabase email OTP through a same-origin HttpOnly/SameSite=Strict cookie; expiry comes from the provider. Durable token-hash registrations deny revoked sessions, including writes rechecked in the same transaction. Registry capacity is 5,000 retained registrations; expired metadata is not yet pruned. Access revocation cannot erase downloaded plaintext or rotate known keys.
- Encryption: random 256-bit browser root and separate random recovery secret; AES-GCM with authenticated vault/domain/object/revision/epoch context; HKDF domain separation; epoch1 only. Memory keys clear on lock/account switch/reload and 15min inactivity. Local browser records and sync journal bases remain plaintext; locking is an app access boundary, not encrypted local storage.
- Consent: existing local/Showcase records do not silently enter an account. Health transfer is separately enabled per unlocked tab; disabling it blocks decrypt/upload/pending replay, but does not delete existing cloud ciphertext. Explicit local copy now has selected-domain preview, encrypted backup and atomic account apply; broader selected-domain acceptance remains partial. Account/domain deletion and key rotation remain incomplete.
- Local capacity:32MB per domain,50,000 top-level records,250KB per record,2MB index; schema-specific caps may be lower. Financial observation/history collections now retain records rather than trimming240 entries/600KB. A new capture above50,000 entries or16MB history refuses explicitly. Earlier discarded evidence cannot be reconstructed. Legacy localStorage still has its2MB import bound until explicit migration; IndexedDB migration retains original bytes and publishes the pointer last.
- Cloud capacity: per-tenant Durable Object,32MB retained encrypted rows,50,000 operation receipts. Client refuses near31MB rather than deleting history. Immutable chunks stage before a CAS-protected encrypted catalog; abandoned/old chunks currently remain. Reads page100 records, max500 pages/36MB; upload batches under850KB. This is bounded snapshot synchronization, not a completed incremental lifetime-delta/compaction design.
- Timing: active-page refresh every30s and1s debounce, plus visible/focus/online events; hidden tabs do not poll. Errors pause automatic sync until explicit retry. Local round-trip elapsed timings cover fixture paths only, not a real-time or physical-device guarantee.
- Conflicts: independent identity-bearing Health/Habit additions use a three-way merge; incompatible edits/deletes/reorders preserve local/cloud copies and stop. Finance is one aggregate; concurrent divergence stops, never timestamp-LWW. Accepted finance evidence is compared against base/local/remote before new publication and before local apply; explicit backup replacement is separate and cannot silently overwrite retained cloud evidence. A complete conflict-resolution/export UI remains outstanding.
- Version fences: protocol1; unknown envelopes/journals and strict unknown domain fields fail closed. Legacy schema readers reject the IndexedDB pointer and new optional financial fields rather than rewriting them. No service worker was introduced. Policy2 rejects older/unknown/newer pending queues before replay and retains them. Explicit old-queue recovery UI remains unfinished.
- Recovery: encrypted portable backups have a separate key, authenticated inventory and preview; export downloads contain private material and must remain private. Explicit domain restore preserves prior local data. Source Git/ZIP backups do not protect owner browser records. A code rollback must preserve new data and use a forward-compatible client/recovery path; do not deploy an older writer against new account schemas.
- Public integrations: durable-v1 quote binding is explicit opt-in and fails closed if its policy/binding is missing. It covers supported coin/USD-EUR quote batches only; other public routes are not globally budget-coordinated. No live market/food load or paid quota was activated. Food uses explicit barcode lookup, no image/diary upload, and manual fallback.
- Release gates: any unresolved isolation/key/data-loss/financial-conservation/secret/execution defect blocks affected activation. Full source-bound build/browser/security, independent review, owner configuration, backups and physical-device journeys precede any separately authorized rollout. PR20 stays draft.
