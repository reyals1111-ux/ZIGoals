# Isolated cloud-data deletion: implemented slice and open gates

The inactive, isolated private-sync Worker now accepts an authenticated `POST /v1/account` request with the exact `delete-cloud-data` confirmation action. Within one Durable Object storage transaction it removes active vault ciphertext, receipts and sessions, then retains a terminal `account-deleted` marker. Later vault reads/writes and session registration for the same verified account return `ACCOUNT_DELETED`; another account is unaffected. A vault page read holds its marker, session, records, revision and manifest in one transaction, so it cannot mix pre- and post-deletion state. A read already in flight before deletion can still return its earlier snapshot. The app has no route or user flow invoking this action, and no hosted Worker was deployed or called.

This is **not full account deletion**. The Supabase identity remains, local copies on other devices remain, and infrastructure recovery or backups may retain prior bytes. [Cloudflare documents point-in-time recovery for SQLite-backed Durable Objects for 30 days](https://developers.cloudflare.com/durable-objects/api/sqlite-storage-api/); restoring a pre-deletion point could also remove the in-object terminal marker. Before live activation, implement an external deletion ledger or equivalent restore control that reapplies the marker, specify actual provider/backup retention, add a guarded app flow that protects unsynced local work, and prove deletion/restore and offline-client journeys on the isolated service. Do not promise instant or permanent erasure from this source slice.

Local evidence: the real Miniflare lifecycle test covers invalid confirmation, revoked-session refusal, more than one 128-key removal batch, terminal reads/writes/reenrollment after restart and another account's continuity. A deterministic overlap test checks one consistent earlier read, deletion waiting for that read, and later 410. Focused 2/2 and full unit 1,358 passed with one explicit skip at source `75813a1`; scoped lint and diff check passed. An independent bounded review found no remaining Critical/Important defect in this source slice after the read transaction fix, while retaining the recovery caveat. Tests do not establish a hosted service, provider-account deletion, physical devices, backup expiry or full E04 acceptance.
