# Session revocation integration
Selected policy: durable access revocation, with explicit disclosure that downloaded data and recovery-secret knowledge cannot be revoked. Cryptographic root/domain-key rotation and account deletion remain incomplete; this is not full ENC-07 acceptance.
Supabase documents that revoked-session access tokens can remain valid until expiry: https://supabase.com/docs/guides/auth/signout . The isolated Worker now authenticates at the provider and checks a durable per-tenant hash-of-token session record. Raw tokens are never persisted by the Worker.
OTP completion must successfully register a new session before the app issues its HttpOnly cookie. Registration of an already revoked token fails; tombstones are retained. Identity checks also require active durable session access. Every vault write rechecks the session inside its transaction so a prior authorization read cannot bypass committed revocation.
Settings lists named active sessions and provides confirmed single-session/all-other-session revocation. Signout attempts both durable revocation and provider logout while always clearing the local cookie; uncertain remote revocation is reported. The app locks its memory key on a denied sync response.
