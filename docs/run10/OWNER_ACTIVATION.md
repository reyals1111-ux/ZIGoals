# Recommended owner setup — isolated nonproduction only
Use Supabase email OTP for identity, a verified SMTP sender for delivery, and the isolated Cloudflare private-sync Durable Object for ciphertext. Encryption/recovery keys are generated only in the browser; Supabase login cannot decrypt records. No paid upgrade is required or authorized by this run.
1. Choose an owner-controlled nonproduction Supabase project/region and test email addresses. Confirm email OTP delivery with a verified sender/SMTP configuration and provider limits. Store credentials in the provider's secret settings, never in chat, source or screenshots. Configure the email template to display the OTP token; the UI accepts6–10digits.
2. After separate owner infrastructure approval, provision only an isolated private-sync Worker/Durable Object, with AUTH_ORIGIN, AUTH_PUBLIC_KEY and exact APP_ORIGIN. The local Worker config is a template, not a live migration authorization. Do not add these bindings to public Alpha without review.
3. Configure the nonproduction app server's ZIGOALS_AUTH_ORIGIN, ZIGOALS_AUTH_PUBLIC_KEY and ZIGOALS_SYNC_ORIGIN. Public auth key is an identifier, not a service-role credential. Service-role/admin keys are neither needed nor accepted in browser code. Verify runtime environment availability on the selected OpenNext host.
4. On desktop, verify real inbox delivery, create the vault and privately save its recovery secret. On a separate physical phone, verify a second real OTP, unlock with that secret, opt into Health only if desired, and execute the ledger's device journeys. Test expiry, wrong code/key, offline conflict, lock/sign-out, restored backup and separate-account isolation.
5. Retain sanitized evidence of the results and observed provider limits. Do not call fixture login “working phone–desktop sync.” Account deletion and key rotation remain incomplete; durable session revocation is locally implemented and tested; hosted activation/release remains gated until required lifecycle and security gaps are resolved.
No project, SMTP account, Worker deployment, live migration or subscription was created. Owner action is setup and later physical-device verification; independent local implementation continues now.
Sources checked: https://supabase.com/docs/guides/auth/auth-email-passwordless and https://supabase.com/docs/guides/auth/auth-smtp . Runtime setup remains unverified until owner-controlled configuration exists.
