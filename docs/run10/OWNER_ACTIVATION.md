# Owner setup — one recommended nonproduction path

Owner confirmed no existing service. Recommendation: **Supabase email OTP + Resend SMTP + isolated Cloudflare private-sync Durable Object**. No account, DNS record, email, deployment, migration or subscription was created. Setup does not clear the implementation/security blockers in REQUIREMENTS.json.

1. Create owner-controlled **nonproduction** Supabase and Resend projects and choose two test inboxes. Select suitable regions. Use existing approved Cloudflare access. Keep free plans initially; confirm console quotas and disable/avoid paid upgrades. Current Resend pricing lists100emails/day on Free; this is not an unlimited or guaranteed entitlement. Supabase/Cloudflare compute, storage and requests have separate limits; review their official pricing before activation.
2. In Resend, verify a dedicated owner-controlled auth sending subdomain (suggested `auth.zigoals.app`). Add exactly the provider-issued SPF/DKIM records through your DNS account; establish DMARC after reviewing existing policy. Do not invent record values or overwrite unrelated DNS. Keep open/click tracking off for authentication. Restrict the sending key to this verified domain where supported.
3. Supabase → Authentication → SMTP: host `smtp.resend.com`, port465(TLS), username`resend`, password=the Resend sending key, From=an address on the verified subdomain. Store the key only in Supabase's configuration. Keep email verification enabled; select an email OTP template containing `{{ .Token }}` (the UI accepts6–10digits). Set the exact approved app origin/site URL and explicit redirect allowlist; no wildcards. Supabase's default SMTP is restricted to team addresses and currently2emails/hour, so it is not friends-ready delivery. Custom SMTP initially has its own30/hour limit; choose a conservative tested rate and confirm project settings.
4. Before infrastructure approval, review `workers/private-sync/wrangler.local.jsonc` and prepare a separate owner-only preview config with a distinct Worker name, exact HTTPS`APP_ORIGIN`, Supabase HTTPS`AUTH_ORIGIN`, and its SQLite Durable Object binding/migration. Do not edit/deploy public Alpha. The required Worker secret/config is`AUTH_PUBLIC_KEY` (Supabase public/anon key, never service-role/admin); the app server needs`ZIGOALS_AUTH_ORIGIN`, `ZIGOALS_AUTH_PUBLIC_KEY`, `ZIGOALS_SYNC_ORIGIN`. No values belong in chat, Git, screenshots or NovaVault. These routes currently read server`process.env`; verify OpenNext runtime exposure on the chosen preview before email acceptance.

Once code/security gates pass and the owner separately approves the exact isolated config, the commands below are the prepared order. `wrangler.preview.owner.jsonc` is deliberately an owner-created reviewed config, not an existing deploy-ready file. Never substitute public Alpha's config/name.
