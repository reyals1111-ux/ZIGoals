# Isolated durable quote path

The app's `/api/market-quotes` GET/POST route selects this path only when trusted server configuration sets `ZIGOALS_MARKET_QUOTES_MODE=durable-v1`. It requires the `MARKET_QUOTES` service binding to this Worker's named `QuoteService` entrypoint. An unknown mode or missing/failed binding returns a degraded version-1 pair envelope; it never retries via the old process-local provider. The default public Worker entrypoint still returns 404. Production Alpha configuration is unchanged.

`app-preview.jsonc` is an isolated app binding template, not deployment authorization. The coordinator additionally requires explicit `MARKET_QUOTE_DISPATCH=durable-v1`, a server-selected opaque `MARKET_ACCOUNT_ID`, `MARKET_POLICY`, and its server-only CoinGecko credential. No policy numbers, periods, credential, usage seed or live-provider activation are supplied by these configs. `MARKET_POLICY` retains the strict adapter schema; fixture policy values in tests are synthetic. Never use the fixture clock flag in an activated environment.

Supported work is up to 64 unique coin/USD-or-EUR pairs per request, using CoinGecko simple-price only. Fresh durable evidence bypasses admission. Equivalent concurrent work gets a terminal `LOCAL_QUEUE` outcome with any retained evidence and never dispatches twice. Owners reserve, own, persist DISPATCHED, perform bounded HTTP, settle and publish through current fences. ZIG uses a separate atomic simple-price batch so a failed ZIG response preserves other coin evidence. Each actual batch is one configured charge; no retries or token fallback are attempted. Dispatched uncertainty is never canceled/refunded; unconfirmed settlement prevents publication.

The version-1 response retains legacy `quotes/error` fields and adds ordered per-pair outcomes, complete/degraded flags and sanitized failures. Updated browser transport accepts an explicitly validated v1 envelope, rejects unknown versions/fields or inconsistent summaries, and separately validates the old unversioned shape for unchanged legacy routes. No versioned response falls through to legacy inference. Legacy stored quote snapshots remain readable and retain original observation times; persisted per-pair attempt history is not implemented. Duplicate failure precedence is explicit in `market-pair-result.ts`.

This is **not whole-provider protection**. `market-history-service.ts`, `market-insights-service.ts`, catalog and legacy-default quotes still import the process-local `coinGeckoProvider`. RWA quotes return UNSUPPORTED in durable mode; >64 pairs return LOCAL_QUEUE without I/O. Native ZIG token fallback, shared catalog/history/insights, durable fairness/followers, circuit breakers, tombstone pruning/period rollover, metrics and workload capacity evidence remain incomplete. Force-refresh cannot bypass the shared fresh cache. The adapter still caps retained work/attempts and fails closed at exhaustion.

Local acceptance uses `scripts/run10/market-dispatch.test.mjs`: real named service binding, SQLite Durable Objects, fixture-only intercepted HTTP, inspection proving DISPATCHED precedes HTTP, concurrent equivalent callers, partial Bitcoin/ZIG outcomes, unsupported RWA and restart cache reuse. `market-runtime.test.mjs` retains the independent transition/crash/fence checks. Unit tests cover app-route selection, missing binding, private input rejection, no unconfirmed dispatch/publication, strict wire validation and deterministic failure precedence. No real provider call, key, hosted deployment or phone acceptance is established by these fixtures.

Focused verification on Node 24.19.0 / pnpm 11.19.0: 33 unit tests across six files passed; both actual Workers runtime tests passed; full TypeScript and scoped ESLint passed. Browser transport also ages an originally fresh pair into stale/degraded without changing source timestamps. Red/green logs and existing-file backups are in ignored `.superpowers/run10/market-dispatch/`. The initial runtime attempt was blocked by sandbox localhost-listener permissions; the successful rerun had local listener permission and intercepted every provider request. The isolated app config is a source template; a complete built-OpenNext preview and hosted rollout were not exercised.

Activation remains gated on implementing the remaining required provider paths/policy/recovery/acceptance, measured workload, current usage reconciliation, exact reset timezone and endpoint costs. For an explicitly approved isolated rollout, bind the named service and verify one bounded supported quote plus unavailable/backend-failure behavior. Roll back by removing the app's mode/binding together; that restores the explicitly legacy per-process path, never a claim of global protection. Preserve durable state and tombstones during rollback; do not reset counters to recover capacity. Contract, auth, private sync and production deployment gates are unchanged.
