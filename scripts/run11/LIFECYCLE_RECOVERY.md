# Lifecycle recovery — local prerequisite, not hosted activation
The authority is the separate `LifecycleAuthority`; active deletion and every domain generation are monotonic. Vault snapshots cannot override it. Simultaneous authority rollback requires an externally preserved checkpoint; this code cannot infer missing history from two stale stores.
`LifecycleRecoveryAdmin` is a separate named service entrypoint. No app/public route or production configuration binds it. Bind it only to separately authorized administration; `x-verified-account` selects one account, not caller authentication. The ordinary lifecycle service rejects `/admin*`.
Export with internal `GET /admin/export` and the account UUID header. Preserve the returned `checkpoint` and canonical SHA-256 `digest` outside both vault and lifecycle recovery storage, with an independently maintained account inventory and latest-decision record. Capture after deletion decisions; an older export cannot prove absence of newer deletion.
Before restoring, put the authority in `RECOVERY_MODE=reconcile`; normal lifecycle reads/writes then return503, so the private-sync worker denies reads, writes and reenrollment. Never switch to serving just because storage restoration completed.
For one account at a time, configure externally preserved `RECOVERY_ACCOUNT_ID` and `RECOVERY_CHECKPOINT_SHA256`; these are not accepted from the import body. Keep the original checkpoint envelope available for audit.
Send the checkpoint object to internal `POST /admin/dry-run`, then `/admin/reconcile`. Both validate the external anchor and complete receipt ledger. Dry-run does not write. Reconcile atomically merges account deletion, provider deletion progress, domain generation maxima and operation receipts; incompatible histories fail409.
Import has a16MiB byte limit. Domain operation receipts remain bounded at50,000 per account and reconciliation receipts at128; capacity fails closed. No tombstone or receipt compaction is currently permitted: shortening retention requires a separately reviewed proof that old clients and restored snapshots remain fenced.
Lost acknowledgements replay the persisted digest receipt. Restart does not lower generations. A historical checkpoint cannot undo a newer account deletion or reduce a domain generation. Missing or conflicting receipt history is an administrative error, not permission to reset it.
Re-export and verify the result against the dry-run result digest and external latest-decision inventory. Reconcile every restored account before an owner-authorized return to `serve`; a single account's receipt does not certify the entire restored population. No automatic activation is implemented.
If the latest external checkpoint or complete account inventory is unavailable, keep recovery paused. The code cannot guarantee protection from a simultaneously stale vault, authority and external checkpoint; substituting an older trusted hash does not establish freshness.
Run `pnpm exec vitest run scripts/run11/lifecycle-recovery.test.mjs scripts/run11/lifecycle-runtime.test.mjs scripts/run11/domain-deletion.test.mjs` for controlled local Worker evidence. The simultaneous rollback case copies fictional local SQLite state, pauses serving, reconciles a checkpoint retained outside that copy and verifies old-client denial.
Hosted point-in-time recovery, owner administration bindings/credentials, external checkpoint custody/automation and activation remain external work. These tests do not establish hosted backup erasure or remote deletion of previously downloaded plaintext.
